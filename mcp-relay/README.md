# IRIS MCP 중계기 (mcp-relay)

AI 세션(클로드코드·코덱스)이 시작될 때 MCP 서버를 전부 켜지 않습니다. 세션은 **메뉴판**(저장된 도구 목록)만 받고, 실제 MCP 프로그램은 그 세션이 **처음 도구를 쓸 때** 그 세션 전용으로 켜집니다. 세션이 끝나면 그 세션의 MCP만 함께 끝납니다.

## 어떻게 동작하나

1. 클로드·코덱스 설정의 MCP 항목은 이름·환경변수·권한 설정을 그대로 둔 채, 실행 명령만 작은 **안내원**(`relay.py shim`)으로 바뀝니다.
2. 세션이 시작되면 안내원이 메뉴판으로 목록 요청에 답합니다. 이때 실제 MCP는 켜지지 않습니다.
3. 첫 도구 호출이 오면 실제 MCP를 켜고, 이후 모든 메시지를 그대로 전달합니다.
4. 세션이 끝나면(입력이 닫히거나 강제 종료되면) 그 세션의 MCP가 함께 끝납니다(윈도우 Job Object).
5. **공용 중계기**(`relay.py daemon`, 127.0.0.1:3461)는 IRIS가 시작될 때 하나만 뜹니다. 하는 일은 새 MCP 전환, 메뉴판 갱신, 남은 프로그램 청소, 상태 보기입니다. 꺼져 있어도 세션의 MCP는 동작합니다.

## 명령 (설치 폴더의 동봉 파이썬으로 실행)

```text
python -I relay.py status            지금 무엇이 중계되고 무엇이 켜져 있는지, 오늘 생긴 문제
python -I relay.py sync              새로 더한 로컬 MCP를 전환할 계획 보기(바꾸지 않음)
python -I relay.py sync --apply      그 계획대로 전환(바꾸기 전 설정 복구본을 남김)
python -I relay.py survey --missing  메뉴판이 없거나 낡은 MCP를 한 번씩 켜서 메뉴판 만들기
python -I relay.py restore --all     전부 직접 연결로 되돌리기(서버 하나만이면 --id <id>)
python -I relay.py relay --id <id>   되돌렸던 항목을 다시 중계
python -I relay.py daemon --stop     공용 중계기 끄기
```

## 지원하는 것과 하지 않는 것

- **중계:** 로컬에서 실행되는 MCP(파이썬·node·uvx·npx·`.cmd`·`cmd /c` 등)
- **직접 유지:**
  - 원격 HTTP MCP — 로컬 프로세스가 없어 절감 효과가 없습니다.
  - 플러그인이 띄우는 MCP
  - 제외 목록 — 상태 폴더 `settings.json`의 `exclude`, 기본값은 `self-improve`입니다.
  - 꺼진 항목
  - git 저장소 안의 `.mcp.json`
- **메뉴판:** 리소스·프롬프트 목록은 조사 시점의 사본입니다. 실제 서버를 켰을 때 다르면 클라이언트에 변경을 알리고 메뉴판을 고칩니다(코덱스는 다음 세션부터 반영됩니다).

## 문제가 생기면

- 도구 호출이 `[IRIS MCP 중계기]`로 시작하는 오류를 내면, 서버 이름·실패 단계·요청 실행 여부가 함께 적혀 있습니다.
- 원인은 `relay.py status`의 "오늘 생긴 문제"와 상태 폴더 `logs\`에서 볼 수 있습니다. 기록에는 비밀값이 남지 않습니다.
- 바로 예전처럼 쓰려면 `relay.py restore --all`을 실행합니다. 그 뒤 새로 여는 세션부터 직접 연결입니다.
- 파이썬조차 실행되지 않으면 상태 폴더 `backups\<시각>\`의 설정 복구본(`index.json`에 원래 위치가 적혀 있음)을 원래 자리에 복사합니다.

상태 폴더 위치: `<설치 폴더>\_agent\shared\mcp-relay\`
