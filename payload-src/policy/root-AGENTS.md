# IRIS Workspace — 전역 지침

이 파일은 모든 하위 작업 폴더에서 공통으로 읽는 규칙 원본이다. IRIS 형식의 폴더와 목록 카드 체계를 사용하며, 각 하위 지침에는 자기 레벨에 고유한 규칙만 둔다.

## 사용자 응대

- 전문용어는 처음 나올 때 쉬운 말로 풀고, 한 번에 한 생각씩 설명한다.
- 실행 전에는 무엇을 할지 알리고, 완료 후에는 결과와 남은 일을 쉬운 말로 보고한다.
- 정말 필요한 결정만 한 번에 하나씩 묻는다. 이미 승인·위임된 범위는 반복 확인하지 않는다.
- **선택형 질문 도구(버튼·라디오·체크박스 형태의 질문 UI)를 쓰지 않는다.** 물어볼 것은 일반 문장으로 쓰고, 고를 것이 여럿이면 번호 목록으로 보여 준 뒤 사용자가 번호로 답하게 한다.
- 진행 수치를 말할 때는 코드블록 안에 `█`·`░` 20칸, 내림한 퍼센트, 완료 수/전체 수, 상태를 함께 쓴다. 상태는 완료·진행중·대기·막힘·보류만 사용한다. 전체 수를 모르면 `진행중(총량 미확인)`으로 적는다.

```text
전체        [████████████░░░░░░░░]  60%  (3/5)
S01 준비    [████████████████████] 100%  (4/4)   완료
S02 수합    [██████████░░░░░░░░░░]  50%  (2/4)   진행중
```

## 쉽고 명료한 설명

- 첫 2~3문장 안에 결론을 먼저 말하고, 걱정되는 상황이면 아직 망가지지 않은 것·되돌릴 수 있는 것을 함께 밝힌다.
- 성격이 다른 내용(사실·제안·결정·남은 일)을 한 덩어리에 섞지 않는다. 긴 설명은 번호 소제목으로 나눈다.
- 독립된 항목은 번호를 붙여 한 항목에 하나의 핵심 문장만 쓰고, 핵심어만 굵게 표시한다.
- 전문용어·영어 약어는 처음 나올 때 괄호로 풀이한다. 예: `온셋(onset, 사건이 시작되는 정확한 시점)`.
- `없음`·`아님`·`모름`·`미확인`·`미착수`를 구별하고, 시작하지 않은 일은 `미착수` 또는 `0%`로 분명히 말한다.
- 숫자는 값만 쓰지 말고 계산이나 생활 의미를 함께 적는다.
- 여러 대상을 같은 기준으로 비교할 때만 표를 쓴다. 독립된 항목의 나열은 번호 목록으로 둔다.
- 순서가 있는 과정이 3단계 이상이면 `① 단계명 — 하는 일`을 세로로 쓰고 `↓`로 잇는다.
- 나쁜 소식은 숨기지 않되 바로 뒤에 남아 있는 자료·되돌릴 수 있는 선택을 구체적으로 붙인다.
- 짧게 줄이더라도 중요한 조건·예외·불확실성은 남기고, 제안을 확정 사실처럼 쓰지 않는다.

## 안전

- 사용자 소유 파일·자료·기억·세션·Git 기록을 삭제하거나 덮어쓰지 않는다.
- 결제·발송·게시·예약·제출 등 외부 행동은 기존 사용자 승인 범위에서만 실행한다.
- 시크릿 원문을 지침·코드·등록부·로그에 쓰지 않는다. 금고의 상대경로 포인터만 둔다.
- 바탕화면에는 파일·임시물·캐시를 쓰지 않는다. 바탕화면에 두는 것은 설치기가 만든 「IRIS」 바로가기뿐이다.
- 기존 `.git`은 보존한다. 남의 저장소에서 커밋·브랜치·워크트리를 임의로 만들지 않는다.

## 설계 우선

실질적인 작업 전에는 설계를 독립된 조각으로 나누고, 첫 조각부터 하나씩 쉬운 말로 설명하며 빈틈·위험·개선안을 함께 점검한다. 사용자 피드백으로 해당 조각을 확정한 뒤 다음 조각으로 넘어가며 모든 조각이 확정된 뒤 실행한다. 전문용어는 처음 나올 때 풀이한다. 사용자가 특정 하위 영역의 상시 설계를 명시적으로 위임하고 그 하위 `AGENTS.md`가 자체 설계·독립 비판·수정·검증을 규정한 경우에만 사용자 확정 대기를 그 절차로 대체한다. 사람이 해야 하는 행위, 되돌리기 어려운 외부 결정, 지출·권한 확대는 이 예외의 승인이 아니다. 사용자의 현재 명시적 지시와 이미 허용된 범위를 먼저 확인하며, 이 규칙은 스킬의 작업 방식보다 우선한다.

## 🔴 중계기 항상 경유 — 직결 금지

- 이 PC의 모든 Claude API 호출은 세션 환경변수 `ANTHROPIC_BASE_URL`이 가리키는 **중계기(127.0.0.1:3456)** 를 지나는 것이 유일한 경로다. 중계기는 사용자의 구독으로 호출을 대신 내보낸다.
- **어떤 방법으로도 중계기를 우회해 API에 직결하지 않는다.** 환경변수를 지우고 실행하기, SDK의 주소 덮어쓰기, 공급자 주소로 직접 보내는 요청(토큰 1개짜리 확인용 호출 포함)이 전부 해당한다. 직결은 구독이 아니라 **사용량 요금**을 발생시킨다.
- 429·한도 초과·중계기 오류가 나도 우회하지 않는다. 멈추고 상황을 사용자에게 보고한 뒤 지시를 기다린다.
- 과금 경로를 바꾸는 모든 행위는 사용자의 명시적 사전 승인이 있어야 한다.
- 보조 에이전트를 부를 때 이 규칙을 지시문에 함께 전달한다. 보조가 대신 우회하는 것도 같은 위반이다.

## 🔴 프로세스 종료

- 종료는 **자기가 직접 띄웠고 PID(프로세스 고유번호)를 기록해 둔 프로세스만** 한다.
- **이름 기반 일괄 종료 절대 금지**: `Get-Process node | Stop-Process`, `taskkill /IM node.exe`, `pkill node` 같은 명령 전부. 중계기가 node로 돌기 때문에 node를 한 번 일괄 종료하면 모든 에이전트 세션이 동시에 끊긴다.
- **포트 3456(중계기)·3457(대시보드)·3458(IRIS 창 데몬)에 속한 프로세스는 PID를 알아도 종료하지 않는다.** IRIS 창 데몬은 모든 창 세션의 부모라, 그 PID 하나를 종료하면 세션 전부가 명령을 낸 자신까지 함께 사라진다. 포트·pid 파일·명령줄로 PID를 알아내 종료하는 것, 종료 API를 호출하는 것도 같은 행위다.
- 데몬 코드를 고쳤으면 **파일 저장까지만** 하고 "지금 세션 N개가 끊깁니다"라고 알린 뒤 사용자가 전원 단추로 다시 실행한다.
- 기계 가드: `_agent\claude\scripts\block-blanket-kill.ps1`(Claude·Codex 공용 PreToolUse 훅)이 위 패턴을 차단한다. 차단되면 우회하지 말고 대상 하나를 PID로 특정한다.

## 파일 쓰기 경로 검증

- 폴더명을 기억으로 타이핑하지 않는다. 실제 디렉터리 목록에서 이름을 복사하거나, 쓰기 직전 부모 폴더의 존재를 확인한다.
- IRIS 폴더명에는 **한자·가나를 쓰지 않는다**(한글·영어·숫자만). 한자·가나가 든 경로는 실존하는 한글 이름을 잘못 옮겨 지어낸 것이다.
- 쓰기 도구는 없는 중간 폴더를 조용히 만든다. **존재하지 않는 R/D/P/S/T 코드 폴더를 쓰기로 암묵 생성하지 않는다.** 새 위계 폴더는 `mkdir`로 명시적으로 만든 뒤 쓴다.
- 쓰기 결과 뜻밖의 새 R/D/P 폴더가 생겼다면 그 자체가 사고 신호다. 즉시 멈추고 경로를 다시 확인한다.
- 기계 가드: `_agent\claude\scripts\guard-iris-path.py`가 위 세 조건을 차단한다. 차단 메시지가 뜨면 우회하지 말고 `ls`로 실제 이름을 복사해 다시 시도한다.

## 결과물 전달

- 산출물(HTML 보고서·시각화·대시보드·발표 자료)은 **영혼 안 그 작업 폴더에 파일로 저장**하고, 응답에 전체 경로를 적어 사용자가 다시 열 수 있게 한다. IRIS 창이 그 파일을 미리보기로 띄운다.
- **외부 발행 도구(아트팩트)를 쓰지 않는다.** 결과물은 사용자의 컴퓨터 안에 남는다.
- HTML은 **단일 파일**로 만든다. CSS·JS·데이터를 전부 인라인으로 넣고 외부 CDN·폰트 링크를 쓰지 않는다(인터넷이 없어도 열려야 한다). 이미지는 data URI로 넣는다.
- 디자인 지침이 있는 스킬을 쓸 때 디자인 원칙은 그대로 따르고 전달 수단만 로컬 파일로 바꾼다.

## 폴더 계층

- Role `R0X-한글(English)`: 사용자의 역할.
- Domain `D0X-한글(English)`: 계속 관리하는 분야.
- Project `P0X-한글(English)`: 끝이 있는 구체적인 일.
- Step `S0X-한글(English)`: 일처리 순서의 큰 단계.
- Task `T0X-한글(English)`: 필요할 때만 만드는 세부 작업.
- 코드와 이름은 `-`로 잇고 영문 괄호 앞에는 공백을 넣지 않는다. 요청받은 폴더만 만들며 기존 번호를 다시 매기지 않는다.
- D가 표준 S 구조를 선언했다면 새 P와 함께 해당 S·미니 지침을 만들 수 있다.
- 모든 위계 폴더·재사용 유틸에는 고유 정체성 한 줄과 상위 규칙 재서술 금지 주석을 담은 `AGENTS.md`, `@AGENTS.md` 한 줄짜리 `CLAUDE.md`를 만든다.
- R·D·P의 `AGENTS.md`에는 온톨로지 머리말 카드도 만든다. S·T는 별도 카드를 만들지 않는다.
- 재사용 유틸 이름은 `_english-lowercase` 형식만 쓴다. 소문자 영어 여러 단어는 `-`로 연결한다.
- 산출물·원문·촬영 자료를 담기만 하는 폴더는 이름이 아니라 내용으로 서랍을 판정하고 부모 R·D·P 카드의 `drawers:`에 상대경로를 선언한다. 서랍은 위계 코드를 강제하지 않으며 선언된 서랍과 그 하위에는 지침 파일을 만들지 않는다.
- 프로그램이 만들고 지우는 자동 출력 폴더, 코드 저장소 내부·vendor 원본·에이전트 홈·캐시·`.git` 내부에는 지침을 주입하지 않는다. 재사용 `_` 유틸 자체는 면제하지 않는다.
- `.NN` 미세 하위 표기는 표준 위계로 표현할 수 없을 때만 쓴다. 물리적으로 형제 폴더이므로 의미상 부모의 지침이 자동 상속된다고 가정하지 않는다.
- 도메인 그룹은 실폴더 대신 `〖그룹〗D01-이름(English)` 접두를 쓰며 `〗`와 D 사이에 공백을 넣지 않는다. D 번호는 그룹 안에서 새로 시작한다.
- 세부영역 형제 D는 같은 번호·서로 다른 태그로 구별하며, 무태그 D 하나를 표준·공통 도메인으로 둘 수 있다. 그룹 접두 안에서는 번호가 단계이고 분야는 이름으로 구분될 수 있다.

## 태그 용도

반전각 `〖 〗`의 용도는 아래 11종으로 닫혀 있다. 새 용도는 이 파일과 `IRIS-온톨로지.md`를 먼저 고친 뒤 쓴다. 한 폴더에 서로 다른 종류를 섞지 않는다. 소프트웨어/산출물 종류에 한해 ` 〖Web〗〖App〗`처럼 같은 종류 태그의 복수 병기를 허용한다. 전각 `【 】`·대괄호·중괄호는 폴더명에 쓰지 않는다.

| 용도 | 적용 범위·예시 |
|---|---|
| 기간/연도 | P: `〖2026년.1학기〗`·`〖2026년〗`·`〖2026년 여름방학〗` |
| 소프트웨어/산출물 종류 | P: `〖MCP〗`·`〖Web〗`·`〖App〗`·`〖Local App〗`·`〖Plugin〗` |
| 담당자 | P: `〖홍길동 담당〗` |
| 가족 구성원 | 보험 분야 P의 주피보험자: `〖남편〗`·`〖아내〗` |
| 학년반·분반 | T: `〖1학년 1반〗`·`〖A반〗` |
| 연도·학년반 | 담임 분야 P: `〖2026년 1학년 5반〗` |
| 세부 지역 | 여행 분야 P: `〖제주〗`·`〖오사카〗` |
| 세부영역 | 연구 D: 같은 D 번호, `〖물리학〗`·`〖물리 교육〗` |
| 논문 단위 | 같은 주제에서 갈라지는 연구 P: `〖석사논문〗`·`〖방법론〗` |
| 확장 포인트 | 순차 확장 여정 P: `〖베이스라인〗`·`〖센서 추가〗` |
| 도메인 그룹 접두 | D 코드 앞: `〖교재〗D01-…`, 그룹 안 D 번호 새 시작 |

※ `세부 지역`·`논문 단위`·`확장 포인트`는 폴더 이름으로 자동 판정하지 않는다. 해당 P 카드의 `tags:`에 `kind`를 직접 적는다(적기 전까지 `미분류`로 기록되고 이름 검사가 실패한다).

## 목록 카드와 정본

- 목록 카드의 종류·고유번호·관계·상태 체계·이름 검사 정본은 IRIS 루트 `IRIS-온톨로지.md`다. 종류 목록·관계 14종·검사 14종을 하위에서 임의로 늘리지 않는다.
- 폴더명이 코드·태그의 원본이다. R·D·P 카드의 고유번호(`id:`)는 한 번 부여하면 유지한다. 개명·이동 전에 `aliases:`에 옛 이름을 남긴다.
- 관계는 의존하는 쪽 한 곳에 적는다. 역방향은 도구가 계산한다.
- `canonical`은 방법·표준의 정본, `truth`는 현재 상태를 읽을 자리다. 카드에 현재 상태 값을 복사하지 않는다. `status_scheme: none`인 P에는 `truth`가 필수가 아니다.
- 외부 사람·도구·계정·저장소는 `_ontology/registry.yml`에서 실제 필요한 항목만 관리한다. 비밀값은 넣지 않는다.
- `soul-state.json`은 설치 엔진의 상태 기록으로 보존한다. 설치 식별자와 온톨로지 카드 고유번호를 서로 바꾸거나 복사하지 않는다.

## 조회·갱신·검사

- 세션을 시작할 때 `python _ontology/check_fresh.py`를 실행한다. 훅이 이미 실행했으면 그 결과를 확인하며, 훅이 있다고 추정만 하지 않는다.
- 신선도 불일치면 `python _ontology/build_graph.py --compile`로 재생성한다. 새 R·D·P에는 먼저 `--init` 초안을 검토한 뒤 `--init --write`로 카드를 붙인다.
- 항목은 `python _ontology/query.py where "검색어"`, 정본은 `canonical "ID 또는 상대경로"`, 들어오는 참조는 `inbound "ID 또는 상대경로"`로 찾는다. 실제 파일도 확인한다.
- R/D/P 생성·개명·이동·격리 또는 카드·등록부·명세 변경 뒤에는 같은 턴에 카드 확인 → `build_graph.py --compile` → `validate.py` → `_ontology/render_view.py` → `check_fresh.py` 순서로 갱신한다. 모든 명령은 IRIS 루트에서 실행한다.
- `_ontology/graph.json`과 `IRIS-온톨로지-뷰.html`은 생성된 거울이다. 손으로 수정하지 않는다.
- 최신 판정이 업무 상태 확인이나 모든 규칙 통과를 뜻하지 않는다. 검증 리포트의 실패·경고·해석됨·검사 대상 없음·검사 불가를 구분하고, 명령 종료 성공만으로 규칙 통과라고 보고하지 않는다. 규칙 실패를 근거로 자동 개명·이동하지 않는다.

## 지침과 작업 범위

- 실행 폴더와 모든 조상 `AGENTS.md`를 함께 적용한다. 전역은 루트, 역할 정체성은 R, 분야 규칙은 D, 프로젝트 고유사항은 P에 둔다.
- 지침 이외의 스킬·도구·설정·기억이 중간 조상 폴더에서 자동 상속된다고 가정하지 않는다. 전역 능력은 사용자 전역 연결부, 특정 영역 전용 능력은 해당 영역에 둔다.
- 작업 뿌리 표식은 `soul-state.json`이다. IRIS 루트에 표지판용 빈 git 저장소를 두지 않으며, 기존 코드 저장소의 `.git` 경계는 그대로 존중한다.
- 기억은 에이전트마다 자기 기억을 쓴다. 서로의 기억을 합치거나 옮기지 않는다.

## 도구 규칙

- **문서 분담.** 문서를 *만들고 고치는* 일은 문서 스킬(`document-skills`)로 한다. 계산·재계산·렌더·형식 변환·PDF 출력처럼 라이브러리가 못 하는 일만 문서 MCP(엑셀·워드·파워포인트·PDF·한컴 엔진)에 넘긴다. Office나 한컴이 설치돼 있지 않으면 그 기능은 `대기(pending)` 상태이며, 없는 채로 흉내 내지 말고 무엇이 없어서 못 하는지 사용자에게 알린다.
- **브라우저.** 사람처럼 클릭·입력·스크롤이 필요한 일은 Playwright MCP(Edge 사용)로 한다. Edge가 없으면 브라우저 조작은 `대기` 상태다. **결제·발송·삭제·제출의 마지막 클릭은 사용자가 한다** — 지시받지 않은 제출·결제·발송을 하지 않는다. 주소만 읽으면 되는 일은 브라우저 대신 일반 내려받기를 쓴다.
- **이미지 생성.** `python _agent\claude\tools\gen-image.py --prompt-file <프롬프트.txt> --out <저장경로.png>` 한 명령으로 만든다. 도구가 구독 경로를 먼저 쓰고 안 되면 API로 넘어가며, 마지막 줄에 어느 경로였는지 적는다. API 키가 없으면 이미지 생성은 `대기` 상태다. 글자가 들어가는 이미지는 문구를 프롬프트에 정확히 적어 통째로 생성한다.
- **시크릿.** 모든 키는 `_agent\claude\secrets\.env` 한 곳(`KEY=VALUE`)에서만 관리한다. 지침·코드·로그·등록부에 키 원문을 절대 넣지 않고, 필요할 때 그 파일에서 읽어 환경변수로 주입한다.
- **HWP/HWPX 양식.** 적용 순서는 ① 사용자가 지정한 양식 → ② 기관 공식 양식·사용자가 준 원본 → ③ 가장 가까운 하위 `AGENTS.md`의 양식 → ④ `_document-templates\IRIS-HWPX-기본양식.hwpx`다. 세부 수치는 같은 폴더의 `IRIS-HWPX-기본양식-스타일.md`를 따른다. 납품 전에는 렌더한 PDF를 `_document-templates\iris_hwpx_layout.py check`로 검사해 쪽 배치(상단 시작·제목 고아 금지·셀 중간 잘림 금지)를 통과시킨다.

## 윈도·한글 환경 기술 규칙

1. **셸 heredoc은 한글·인용부호·백슬래시를 깨뜨린다.** 한글이나 `\`가 든 파일 작성·수정은 반드시 쓰기·편집 도구로 하고, 실행이 필요하면 파일을 먼저 만든 뒤 실행한다. 만든 스크립트 안의 일반 문자열도 같은 이유로 깨지므로 윈도 경로는 raw 문자열로 쓴다.
2. **PowerShell 5.1용 `.ps1`에 한글이 들어가면 UTF-8 BOM을 정확히 하나 붙여 저장**한다. BOM이 없으면 ANSI로 읽혀 한글·경로가 깨진다.
3. **PowerShell의 `Get-Content`·`Set-Content`·`Add-Content`·`Out-File`로 UTF-8 텍스트를 고치면 한글이 영구 파손된다.** 파일 편집은 편집 도구나 파이썬으로 하고, PowerShell로 써야 하면 `-Encoding utf8`을 반드시 붙인다.
4. **파이썬이 한글·특수문자를 출력하면 콘솔 인코딩 때문에 죽는다.** 스크립트 첫머리에 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`를 넣고, 인라인 실행이면 명령 앞에 `PYTHONUTF8=1`을 붙인다.
5. **인용부호가 섞이거나 세 줄이 넘는 파이썬은 인라인으로 실행하지 않는다.** 스크래치 폴더에 `.py` 파일로 저장한 뒤 그 파일을 실행한다.
6. **임시 스크립트·내려받기·중간 산출물은 세션 스크래치 폴더의 절대경로에만** 만들고 그 경로 그대로 실행한다. 작업 폴더나 IRIS 루트에 쓴 임시 파일은 끝나기 전에 지운다.
7. **프로그램으로 기존 텍스트 파일을 다시 쓰면 줄바꿈이 CRLF로 바뀌어 원고가 오염된다.** `read_bytes`/`write_bytes`나 `newline="\n"`을 쓰고, 저장 뒤 줄바꿈·BOM이 원본과 같은지 확인한다.
