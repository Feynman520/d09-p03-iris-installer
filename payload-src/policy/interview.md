# 첫 세션 — 폴더 구조 인터뷰 대본

이 문서는 설치가 끝난 뒤 **첫 세션의 비서가 반드시 따르는 대본**이다. 설치기는 일부러 작업 폴더(R/D/P)를 하나도 만들지 않았다.
사용자의 실제 삶과 일에 맞는 구조는 미리 짠 틀이 아니라 **인터뷰**로만 나온다. 비서는 이 대본대로 묻고, 사용자가 확정한 뒤에만 폴더를 만든다.

## 0. 비서가 지킬 규칙

1. 인사는 **두 줄**. 그다음 곧장 1장의 첫 질문으로 들어간다. "무엇부터 할까요?"라고 묻지 않는다.
2. **한 번에 한 질문.** 선택형 질문 도구(AskUserQuestion 등)는 쓰지 않는다. 보기가 필요하면 번호 목록으로 적고 번호나 문장으로 답하게 한다.
3. 전문용어·영어 약어는 처음 나올 때 쉬운 말로 풀이한다(예: "역할(Role, 내가 삶에서 맡고 있는 자리)").
4. 답이 짧거나 막연하면 **예시를 들어 되묻는다.** 예: "예를 들면 직장에서의 자리, 집에서의 자리, 배우는 사람으로서의 자리처럼요."
5. 사용자가 확정하기 전에는 **폴더를 만들지 않는다.** 만들기 전 전체 표를 보여 주고 "이대로 만들까요?"에 "네"를 받는다.
6. 진행 상태를 `_agent/setup/interview-state.json`에 단계마다 저장한다(끊겨도 이어서). 형식은 6장.
7. 이름 규칙은 루트 `AGENTS.md`의 〈폴더 계층〉 절이 정본이다. 대본에 없는 것은 그 절을 따른다.
8. 인터뷰는 보통 10~15분이다. 사용자가 "간단히"를 원하면 역할당 질문을 2개로 줄이되, 역할·영역은 반드시 끝낸다.

## 1. 역할(R) 인터뷰 — 가장 자세히

역할 = 사용자가 삶에서 맡고 있는 **자리**들. 폴더 이름은 `R01-한글(English)` 꼴이다(예: `R01-교사(Teacher)`).

질문 순서(한 번에 하나씩):

1. "지금 하시는 일을 전부 말씀해 주세요. 직업 하나만이 아니라, 부업·연구·학습·가정·취미까지 '자리'라고 부를 만한 것을 모두요."
2. 나온 것마다 되묻는다: "그 자리에서 실제로 반복해서 하는 일은 무엇인가요?" (3가지 이상 나오게)
3. "그 자리의 일을 남에게 설명한다면 한 문장으로 뭐라고 하시겠어요?" → 폴더의 한 줄 정체성 문장으로 쓴다.
4. "혹시 빠뜨린 자리가 있을까요? 예: 가족 안에서의 자리, 재정 관리, 건강, 배우는 사람, 만드는 사람(글·영상·코드)."
5. 역할이 다 모이면 **중요도 순서**를 묻는다: "가장 시간을 많이 쓰는 순서대로 번호를 매겨 주세요." → 그 순서가 R01, R02…가 된다.
6. 역할마다 한글 이름과 영어 이름을 **제안**하고 고치게 한다. 영어 이름은 짧은 명사(첫 글자 대문자). 예: 교사(Teacher) · 개발자(Developer) · 연구자(Researcher) · 부모(Parent) · 학습자(Learner).

확정 문장 예: "역할은 3개입니다. R01-교사(Teacher) · R02-연구자(Researcher) · R03-부모(Parent). 맞나요?"

## 2. 영역(D) 인터뷰

영역 = 한 역할 안에서 **반복되는 큰 갈래**. 폴더 이름은 `D01-한글(English)`. 보통 역할당 3~7개.

역할마다 반복한다:

1. "R01-교사 자리에서 일의 큰 갈래를 나눈다면 어떻게 나뉘나요? 예: 수업 · 담임 · 행정 · 연구회."
2. 갈래마다 "그 갈래에서 지금 실제로 하는 일이 있나요?" (없으면 만들지 않아도 된다고 안내)
3. 이름 제안 → 확정. 영역 이름은 분야·기능 이름으로(사람 이름·연도 금지).
4. 같은 분야인데 세부만 다르면 하나의 D로 두고 나중에 태그로 가르자고 안내한다(루트 AGENTS.md 〈세부영역〉).

## 3. 프로젝트(P) 인터뷰

프로젝트 = 영역 안에서 **시작과 끝이 있는 일**. 폴더 이름은 `P01-한글(English)`, 필요할 때만 뒤에 반전각 태그 `〖 〗`(기간·종류 등).

영역마다:

1. "이 갈래에서 **지금** 진행 중이거나 곧 시작할 일이 있나요? 없으면 비워 두어도 됩니다."
2. 있는 것만 이름을 정한다. 기간이 중요한 일이면 태그를 제안한다(예: `〖2026년.2학기〗`).
3. 단계(S)·세부(T) 폴더는 지금 만들지 않는다 — 일을 시작할 때 만든다고 안내한다.

## 4. 확정과 생성

1. 전체 트리를 표로 보여 준다(폴더 이름 · 한 줄 정체성).
2. "이대로 만들까요?" → "네"를 받은 뒤에만 진행한다. 고칠 것이 있으면 그 자리에서 고치고 다시 보여 준다.
3. 폴더를 만든다. 폴더마다 `AGENTS.md`(그 폴더의 한 줄 정체성 + 무중복 가드 주석)와 `CLAUDE.md`(`@AGENTS.md` 한 줄)를 함께 만든다. 루트 `AGENTS.md`의 규칙을 하위에서 되풀이하지 않는다.
4. 목록 카드와 그래프를 만든다: 루트에서 `python _ontology/build_graph.py --init --write` → `python _ontology/build_graph.py --compile` → `python _ontology/render_view.py`. 실패하면 오류 문장을 그대로 보여 주고 멈춘다(추측으로 고치지 않는다).
5. `_agent/setup/interview-state.json`의 `state`를 `done`으로 적는다.
6. 마지막으로 만들어진 트리를 다시 보여 주고, **그때** "이제 무엇부터 할까요?"를 묻는다.

## 5. 하지 말 것

- 사용자가 말하지 않은 역할·영역을 지어내 넣지 않는다(예시는 예시라고 말한다).
- 한 번에 여러 질문을 몰아 묻지 않는다.
- 폴더 이름에 대괄호 `[ ]`·중괄호 `{ }`·슬래시를 쓰지 않는다. 태그는 반전각 `〖 〗`만.
- 확정 전에 폴더를 만들거나, 만든 뒤 사용자 동의 없이 지우지 않는다.

## 6. 진행 상태 파일 형식

`_agent/setup/interview-state.json`

```json
{ "schema": 1, "state": "roles | domains | projects | confirm | done", "roles": [], "domains": [], "projects": [], "updatedAt": "ISO 시각" }
```

세션이 끊겼다가 다시 열리면 이 파일을 읽고 "지난번에 여기까지 정했습니다"라고 보여 준 뒤 이어서 묻는다.
