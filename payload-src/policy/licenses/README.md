# payload-src/policy/licenses — 부품 허가서 사본이 모이는 자리

동봉하는 부품마다 그 부품을 만든 사람이 붙인 **허가서(license, 이 소프트웨어를 어떤 조건으로 써도 되는지 적은 글)** 원문 사본을 여기에 모은다. 배포되는 zip에서는 `payload\policy\licenses\`가 되고, 설치된 뒤에는 사용자가 "IRIS가 무엇으로 만들어졌는지"를 볼 수 있는 자리다.

## 어떻게 채워지나

- **자동(대부분).** 부품 수집 단계(T07)가 `lock.json`의 각 부품에서 `LICENSE`·`LICENSE.txt`·`COPYING` 류를 찾아 이 폴더로 복사한다. 파이썬 바퀴집(`wheelhouse`)처럼 항목이 많은 부품은 하위 폴더로 모은다. 자동 수집물은 **손으로 고치지 않는다** — 원본이 바뀌면 다시 수집한다.
- **수동(여기 직접 넣는 것).** 허가서 원문 파일이 저장소·패키지 안에 없고 README나 웹페이지에만 적혀 있는 부품은 자동 수집이 아무것도 가져오지 못한다. 그런 부품은 사람이 원문을 받아 이 폴더에 파일로 넣고, 아래 표에 한 줄 추가한다.

## 지금 알고 있는 수동·주의 항목

| 부품 | 무엇이 문제인가 | 해야 할 일 |
|---|---|---|
| `ui-ux-pro-max` (`ui-ux-pro-max-cli`) | CLI 메타데이터는 MIT지만, **함께 들어오는 스킬 자산은 CC-BY-NC-4.0(비상업 사용 조건)** 이라고 패키지 README에만 적혀 있다. 별도 허가서 파일이 없어 자동 수집이 비어 있다. | 패키지 README의 해당 문단을 `ui-ux-pro-max-NOTICE.txt`로 이 폴더에 넣는다. **이 비상업 조건 문구를 허가서 목록·화면 표기에서 지우지 않는다.** |
| `wheelhouse` (문서 MCP 파이썬 바퀴 묶음) | 바퀴마다 허가서가 제각각이라 한 줄로 요약할 수 없다. | 수집 때 바퀴별 허가서를 `wheelhouse\` 하위로 모은다. 빠진 바퀴가 있으면 그 바퀴만 수동으로 채운다. |
| `claude` (Claude Code), `document-skills` | **허가서가 재배포(사본 나눠주기)를 금지**한다. 그래서 zip에 넣지 않고 설치 중에 내려받는다. | **허가서 원문을 이 폴더에 복사하지 않는다.** 대신 부품 이름·출처 주소·허가서 종류만 목록에 적어 사용자가 원문을 직접 볼 수 있게 한다. |

## 규칙

- 이 폴더에는 **허가서·고지 원문만** 둔다. 설치기 코드나 사용자 자료를 넣지 않는다.
- 개인 정보·계정·열쇠(API 키)가 들어간 파일을 넣지 않는다. 빌드 정화 검사가 이 폴더도 함께 훑는다.
- 부품을 빼거나 판을 올리면 그 부품의 허가서 사본도 같은 턴에 정리한다. 남아 있는 옛 허가서는 사실과 다른 고지가 된다.
