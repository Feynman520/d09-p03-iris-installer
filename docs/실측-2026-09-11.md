세 가지 사실을 이 PC에서 직접 실행해 확인한 기록. 스크래치 작업(`%TEMP%\iris-spike\`, `C:\비서시험\`)은 전부 확인 후 삭제했다. 프록시(127.0.0.1:3456)는 시작·중지하지 않고 살아 있는 그대로 사용했다.

## 1. 로그인 — 프록시 경유 시 `claude` 자체 로그인 필요 여부

| 항목 | 명령 | 결과 원문(3줄 이내) | 결정 |
|---|---|---|---|
| 깨끗한 설정 홈 + 프록시 경유 1회 실행 | `claude -p "답은 한 단어로: 준비됐나?" --model haiku --tools "" --strict-mcp-config --setting-sources user` (CLAUDE_CONFIG_DIR=스크래치, ANTHROPIC_BASE_URL=프록시) | `Not logged in · Please run /login`（exit 1） | 로그인 필요 판정 근거 |
| 출력모드에서 `/login` 시도 | `claude -p "/login" --model haiku ...` | `/login isn't available in this environment.`（exit 0） | 참고 |
| 대화형 `/login` 시도(stdin에 파이프 후 8초 뒤 PID로 종료, 로그인 미완료) | `claude`(플래그 있음/없음 둘 다 시험) | 두 시험 모두 동일: `/login isn't available in this environment.` | 브라우저 URL 관측 불가 — ANTHROPIC_BASE_URL이 설정된 동안 `/login` 명령 자체가 비활성화됨 |
| 신뢰 대화상자(폴더 신뢰 질문) 관측 여부 | 위 4개 실행 전부의 화면 출력 확인 | 신뢰 대화상자 문구 없음(전부 즉시 "Not logged in" 또는 "/login isn't available"만 출력) | 이 시나리오에서는 안 뜸 |
| 실제 운영 설정 홈 읽기전용 확인(수정 없음) | `Test-Path "<IRIS 루트>\_agent\claude\.credentials.json"` | `True`（파일 존재, 내용은 열람 안 함） | 정상 동작에는 `.credentials.json` 같은 인증 아티팩트가 config 홈에 있어야 함 |

**해석:** 깨끗한 `CLAUDE_CONFIG_DIR`로 프록시를 경유해도 `claude`는 로그인(인증 아티팩트)을 요구한다. 그런데 `ANTHROPIC_BASE_URL`이 설정된 상태에서는 표준 OAuth `/login` 플로우 자체가 "isn't available in this environment"로 막혀 있다. 즉 설치기가 사용자에게 브라우저 OAuth를 띄우는 방식은 이 프록시 경유 환경에서 그대로 쓸 수 없고, 유효한 `.credentials.json`(또는 동등한 인증 아티팩트)을 config 홈에 배치하는 방식이 필요하다는 뜻 — Task 13/14 설계에 반영 필요.

```
login.claudeCliRequired = true
```

## 2. node-pty — 동봉 Node ABI · 한글 경로 · 압축 해제 후 실행

| 항목 | 명령 | 결과 원문(3줄 이내) | 결정 |
|---|---|---|---|
| 포터블 Node v24.17.0 다운로드·해시 대조 | `Invoke-WebRequest .../node-v24.17.0-win-x64.zip`; `Get-FileHash -Algorithm SHA256` | 계산값 `f2aa33b35b75aca5f3f7b85675a6f6423201053e9381911e64961f3bda2528ab` = `SHASUMS256.txt`의 같은 줄 값과 일치 | 해시 일치 확인, lock.json에 그대로 기록 |
| Face를 `C:\비서시험`(한글 경로)로 복사 후 `npm ci` | `robocopy ... /XD node_modules state docs _archive .git`; `npm ci` | `added 19 packages, and audited 20 packages in 2s` / `found 0 vulnerabilities`（node-gyp·컴파일 관련 로그 없음） | 네트워크 컴파일 없이 2초 만에 끝남 |
| node-pty 설치 스크립트 재실행으로 실제 동작 확인 | `node scripts/post-install.js`（node-pty 폴더 안） | `Cleaning release folder... Moving conpty.dll... Copying ... conpty.dll -> build\Release\conpty\conpty.dll`（OpenConsole.exe도 동일） | postinstall은 conpty 바이너리만 복사, `pty.node` 자체는 패키지 안 `prebuilds\win32-x64\pty.node`에 이미 동봉되어 있어 다운로드·컴파일 없이 그대로 로드됨(`lib/utils.js`가 `build/Release`→`prebuilds/<platform>-<arch>` 순서로 탐색) |
| 데몬 단독 실행(한글 경로, 포트 3461) 헬스체크 | `node.exe daemon\server.mjs`(IRIS_FACE_PORT=3461, IRIS_FACE_STATE=스크래치); `Invoke-RestMethod http://127.0.0.1:3461/api/health` | `{"ok":true,"version":"2.30.0",...,"root":"C:\\비서시험","rootName":"비서시험"}` | 정상, 한글 루트 경로 그대로 인식 |
| 세션 생성 POST(pty spawn 실제 시험) | `Invoke-RestMethod -Method Post .../api/sessions -Body '{"cwd":"C:\\비서시험","agent":"claude","model":"haiku","effort":"low"}'` | 200 OK, `{"id":"s1","pid":22532,"status":"busy","cmdline":"claude --model haiku --effort low --session-id ..."}` | pty가 정상적으로 자식 프로세스를 띄움 |

**해석:** node-pty 1.1.0은 Windows x64용 `pty.node`를 패키지 tarball 안에 직접 동봉하고 있어(`node-gyp-build` 방식이 아니라 자체 `scripts/prebuild.js || node-gyp rebuild` 방식이지만 실제로는 prebuild 성공), 새 PC에 빌드 도구(Python·MSBuild 등) 없이도 `npm ci`만으로 즉시 쓸 수 있다. 동봉 Node v24.17.0(ABI/`process.versions.modules`)과 `npm ci`를 실행한 Node가 같은 버전이면 ABI 문제 없음을 실제 pty spawn으로 확인했다. 한글 경로(`C:\비서시험`)에서도 헬스체크·세션 생성·daemon.log 전부 문제없이 동작했다.

```
soulName.koreanAllowed = true
nodePty.abiOk = true
nodePty.npmCiMode = prebuild
lock.parts.node.sha256 = f2aa33b35b75aca5f3f7b85675a6f6423201053e9381911e64961f3bda2528ab
```

## 3. 재배포 권리 — Claude Code npm 묶음 재배포 가능 여부

**판정 규칙(브리프에서 미리 정한 대로 그대로 적용):**
- 허가서가 MIT·Apache-2.0·BSD류 → `bundle`.
- "Anthropic Commercial Terms"·"may not redistribute"·"SEE LICENSE IN"으로 비공개 약관을 가리킴 → `download`.
- 애매하면 `download`.

| 항목 | 명령 | 결과 원문(3줄 이내) | 결정 |
|---|---|---|---|
| claude-code 패키지 팩·`package.json`의 `license` 필드 | `npm pack @anthropic-ai/claude-code@2.1.267`; `tar -xf ...`; `Get-Content package.json` | `"license": "SEE LICENSE IN README.md"` | 규칙상 `download` 대상 문구 |
| `LICENSE.md` 원문(패키지 안에 동봉된 실제 파일, README.md가 아님) | `Get-Content package\LICENSE.md` | `© Anthropic PBC. All rights reserved. Use is subject to the Legal Agreements outlined here: https://code.claude.com/docs/en/legal-and-compliance.` | 전면 저작권 보유(All rights reserved) — 비공개 약관 확정 |
| `README.md` 안에 "license" 절이 실제로 있는지 검색 | `grep -i license README.md` | 매치 없음(README에는 라이선스 절이 없음 — `package.json`이 가리키는 곳과 실제 위치가 다름) | 참고(불일치 관찰) |
| `package.json`의 `version`·`bin`·설치 구조 | `Get-Content package.json` | `"version":"2.1.267"`, `"bin":{"claude":"bin/claude.exe"}`, `optionalDependencies`로 `@anthropic-ai/claude-code-win32-x64` 등 플랫폼별 패키지 지정 | 실제 실행파일은 win32-x64 옵셔널 패키지 안의 `bin/claude.exe`(Task 12 설치기가 참조할 경로) |
| Codex 라이선스·버전·bin | `npm view @openai/codex@0.154.0 license`; `version`; `bin` | `Apache-2.0` / `0.154.0` / `{ codex: 'bin/codex.js' }` | 오픈소스(참고용, 이 Task의 결정값은 claude 재배포 여부만) |
| TeamClaude 라이선스·버전·bin | `npm view @karpeleslab/teamclaude@1.1.16 license`; `version`; `bin` | `MIT` / `1.1.16` / `{ teamclaude: 'src/index.js' }` | 오픈소스 |

**해석:** `@anthropic-ai/claude-code`는 `package.json`의 `license` 필드가 `"SEE LICENSE IN README.md"`이고 실제 동봉 `LICENSE.md`는 "All rights reserved"형 전면 저작권 문구라 판정 규칙에 정확히 해당한다 → `download`. 즉 설치기는 zip에 claude-code를 동봉하지 않고, 설치 시 동봉 Node의 npm으로 `@anthropic-ai/claude-code@2.1.267`을 내려받는 방식(설계 문서 갈림 표의 "download" 분기)을 쓴다. Codex(Apache-2.0)·TeamClaude(MIT)는 오픈소스라 재배포 제약이 없다.

```
lock.parts.claude.redistribute = download
lock.parts.claude.license = SEE LICENSE IN README.md (LICENSE.md 원문: "© Anthropic PBC. All rights reserved. Use is subject to the Legal Agreements outlined here: https://code.claude.com/docs/en/legal-and-compliance.")
lock.parts.codex.license = Apache-2.0
lock.parts.teamclaude.license = MIT
```
