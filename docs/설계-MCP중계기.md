# 설계 — MCP 중계기(mcp-relay)

- 상태: **확정**(2026-10-28). 조각 1은 사용자 피드백으로 확정, 조각 2~11은 사용자가 "추천대로 끝까지"로 위임(같은 날). 설계 대화의 실측 근거는 7절.
- 한 줄 요약: AI 세션은 MCP **메뉴판**(저장된 도구 목록)만 받고, 실제 MCP 프로그램은 그 세션이 **처음 도구를 쓸 때** 그 세션 전용으로 켜지며, 세션이 끝나면 그 세션 것만 함께 끝난다.
- 경로 표기: 설치 경로는 `<설치 폴더>\…`로 적는다(R-038).

## 0. 용어

| 용어 | 뜻 |
|---|---|
| **실제 MCP** | 원래 설정에 적혀 있던 MCP 서버 프로그램(한글·엑셀·플레이라이트 등) |
| **안내원(shim)** | 클로드·코덱스가 MCP 대신 띄우는 작은 파이썬 프로그램. 서버 하나·세션 하나당 하나 |
| **공용 중계기(daemon)** | IRIS 시작 때 하나만 뜨는 관리 프로그램. 메뉴판 갱신·장부 청소·상태 보기 |
| **메뉴판(catalog)** | 실제 MCP가 내놓은 초기화 응답·도구·프롬프트·리소스 목록을 저장한 파일 |
| **등록부(registry)** | "이 안내원이 켤 실제 MCP의 실행 명령"을 적은 파일. 서버마다 한 장 |
| **장부(ledger)** | 지금 켜져 있는 실제 MCP의 주인(안내원) 기록. 비정상 종료 뒤 청소에 쓴다 |

## 1. 조각 1 — 연결 구조 (사용자 확정: ⓑ 서버별 안내원)

- 클로드·코덱스 설정의 MCP 항목은 **이름·범위·환경변수를 그대로 둔 채** 실행 명령(`command`·`args`)만 안내원으로 바꾼다.
  `command = <동봉 python.exe>`, `args = ["-I", "<설치 폴더>\_agent\shared\tools\mcp-relay\relay.py", "shim", "--id", "<등록부 id>"]`.
- 도구 이름(`mcp__<서버>__<도구>`)이 바뀌지 않으므로 기존 권한·승인 규칙·훅·스킬 문서가 그대로 맞는다.
- 세션 구별 = **안내원 프로세스 하나**("이 세션의 이 서버"). 클로드가 주는 `CLAUDE_CODE_SESSION_ID`는 장부 표시용으로만 쓴다(코덱스는 주지 않는다 — 구별에는 필요 없다).
- 세션 종료 = 안내원의 **입력(stdin)이 닫힘**. 강제 종료면 Job Object(묶인 프로세스를 함께 끝내는 윈도우 기능)가 실제 MCP 가계도를 함께 끝낸다. 공용 중계기 장부가 이중 확인한다(3절).
- 종료로 보지 않는 것: AI 답변 완료, 오래 안 씀(유휴 종료 없음), Face 최소화·새로고침·화면 연결 끊김.
- 기각안: ⓐ 서버별 로컬 주소(HTTP) — 중계기 재시작 때 클로드가 다시 붙지 않음(#27142·#50450), HTTP 무응답 제한 5분, 세션 감시를 중계기가 홀로 책임. ⓒ 세션당 안내원 1개 — 도구 이름이 바뀜. ⓓ 만능 도구 — 도구별 승인 우회.

## 2. 조각 2 — 메뉴판과 설정 정본

**정본 3층 — 서로 겹치지 않는다.**

| 층 | 정본 파일 | 담는 것 | 담지 않는 것 |
|---|---|---|---|
| ① 어떤 MCP가 어느 범위에 있나 | 클로드 `.claude.json`·`.mcp.json`, 코덱스 `config.toml`·`.codex\config.toml` (지금과 같음) | 이름·범위·환경변수·켜짐/꺼짐·코덱스 승인 설정 | — |
| ② 실제로 무엇을 실행하나 | 등록부 `<설치 폴더>\_agent\shared\mcp-relay\registry\<id>.json` | 원래 `command`·`args`, 바꾸기 전 원문(복구용), 만든 주체(installer/sync) | 환경변수 값(비밀이 섞일 수 있음) — 안내원이 클라이언트에게서 물려받는다 |
| ③ AI에게 보여 줄 메뉴판 | `…\mcp-relay\catalog\<id>.json` | 서버 이름·설명(instructions)·도구 이름·설명·입력 형식·주석(annotations)·`_meta` | 실행 명령·환경변수·비밀값 |

- **비밀값 분리:** 환경변수는 지금처럼 클라이언트 설정에만 남는다. 클라이언트가 안내원에게 넘기고 안내원은 그대로 실제 MCP에 넘긴다. 등록부·메뉴판·장부·기록 어디에도 환경변수 값을 쓰지 않는다. 기록에는 실행 파일 이름과 인자 개수만 남긴다.
- **id 규칙:** `<agent>.<범위>.<이름>` — 범위는 `global` 또는 `p<설정 파일 경로 sha256 앞 8자리>`. 예: `claude.global.hwp-automation`, `codex.p1a2b3c4d.chuk-mcp-physics`. 클로드와 코덱스는 실행 명령이 다를 수 있어(이 PC의 코덱스 중간 실행기) **따로 등록**한다.
- **메뉴판 지문:** `sha256(실행 명령 + 인자 + 작업 폴더)`. 지문이 다르면 "낡음"으로 본다.
- **처음 만들기(일회성 조사):** 전환할 때 `relay.py survey`가 서버를 **한 번씩** 켜서 메뉴판을 저장하고 바로 끈다. 매 세션 시작 때는 하지 않는다.
- **메뉴판이 없거나 낡았을 때(자가 복구):** 그 세션의 안내원이 시작 단계에서 실제 MCP를 바로 켜서 실제 목록으로 답하고 메뉴판을 새로 저장한다. 그 한 세션만 예전처럼 즉시 켜지고, 다음 세션부터는 다시 늦게 켠다.
- **실제로 켰을 때 최신 형식 확인:** 실제 MCP가 켜지면 안내원이 도구 목록을 한 번 더 받아 메뉴판과 비교한다. 다르면 메뉴판을 갱신하고, 클라이언트에 `notifications/tools/list_changed`를 보낸다(클로드는 반영, 코덱스는 기본값에서 무시 — 다음 세션부터 반영).
- **추가·수정·삭제 반영(`relay.py sync`):** 사용자는 지금처럼 `claude mcp add`·설정 편집으로 MCP를 다룬다. sync가 설정을 훑어서 다음을 한다.
  - ⓐ 새 로컬 실행형 항목 → 안내원으로 전환 + 등록부 + 조사
  - ⓑ 사용자가 안내원 항목을 다른 명령으로 바꿈 → 등록부를 "해제"로 표시하고 손대지 않음
  - ⓒ 설정에서 사라진 항목 → 등록부·메뉴판 정리
  - ⓓ 꺼진 항목(코덱스 `enabled = false`) → 손대지 않음

  sync는 IRIS 시작 때 공용 중계기가 한 번 돌린다(설정 `autoSync`, 기본 켬). 바꾸기 전에는 그 파일의 복구본을 `…\mcp-relay\backups\<시각>\`에 남긴다.
- **범위 보존:** 항목은 원래 있던 설정 파일·범위에서 고친다. 역할·프로젝트 전용 MCP는 그 범위 파일 안에서만 안내원이 된다. 그래서 다른 범위에 새로 노출되지 않는다.
- **편집 방법(덮어쓰기 금지):**
  - 클로드 사용자 설정(`.claude.json`)은 실행 중인 클로드가 계속 다시 쓰는 파일이다. 그래서 그 항목 하나만 바꾸고 원자적으로 저장한 뒤, 다시 읽어 확인한다. 실패하면 다음 sync가 재시도한다.
  - `.mcp.json`도 항목 하나만 바꾼다.
  - 코덱스 TOML은 해당 `[mcp_servers.<이름>]` 블록의 `command`·`args` 두 줄만 바꾼다. 단순한 모양이 아닌 블록은 건너뛰고 이유를 남긴다.

## 3. 조각 3 — 실제 MCP 실행·재사용·정리

- **실행 시점:** 안내원이 `tools/call`·`resources/read`·`prompts/get`·`completion/complete`·구독 같은 **실제 일 요청**을 처음 받았을 때만 켠다. 목록 요청(`initialize`·`tools/list`·`prompts/list`·`resources/list`·`resources/templates/list`·`ping`)과 새 규격 탐색 요청(`server/discover`)으로는 켜지 않는다.
- **동시 요청:** 켜는 중에 들어온 요청은 줄을 세웠다가 순서대로 넘긴다. 켜기는 안내원 안에서 한 번만 일어난다. 그래서 같은 세션 안에서 같은 MCP가 두 번 뜨지 않는다.
- **재사용:** 한 번 켠 실제 MCP는 그 안내원이 끝날 때까지 유지한다. 유휴 종료는 없다.
- **소유:** 실제 MCP는 일시정지 상태(CREATE_SUSPENDED)로 만든 뒤, KILL_ON_JOB_CLOSE Job Object에 넣고 재개한다. 그래서 손자 프로세스까지 빠짐없이 묶인다(node 자식의 손자가 살아남는 것을 실측함). 안내원이 어떤 식으로 죽든 그 묶음이 함께 끝난다.
- **정상 종료:** 입력이 닫히면 실제 MCP의 입력을 닫고 최대 3초 기다린 뒤 Job Object로 정리한다. 클로드는 300ms 뒤 가계도째 끝내고, 코덱스는 자기 Job Object를 끝낸다. 어느 경우든 결과는 같다.
- **COM 프로그램:** 한/글·엑셀·워드처럼 COM으로 따로 뜬 앱은 MCP의 자식이 아니다. 그래서 묶음에 들어가지 않고, 중계기가 강제로 끄지 않는다(지금과 같은 동작).
- **장부:** 실제 MCP를 켜면 `…\mcp-relay\ledger\<안내원 PID>.json`에 기록한다. 안내원 PID와 시작 시각, 실제 MCP PID와 시작 시각, id, 에이전트 종류, 세션 id(있으면)를 담는다. 정상 종료 때 지운다.
- **비정상 종료 뒤 청소(이중 안전장치):** 공용 중계기가 시작 때와 30초마다 장부를 본다.
  - 안내원이 사라졌는데 실제 MCP가 **같은 PID·같은 시작 시각**으로 살아 있으면, 그 실제 MCP의 가계도만 PID로 끝낸다.
  - 이름으로 고르지 않는다. 시작 시각이 다르면(PID 재사용) 건드리지 않는다.
- **오래 걸리는 작업:** 응답이 잠깐 없다는 이유로 끄지 않는다. 시간 제한은 클라이언트 설정이 정한다.

## 4. 조각 4 — 메시지 중계 규칙

- **그대로 통과:** 켠 뒤의 모든 메시지는 **바이트 그대로** 양쪽으로 넘긴다. 이미지·오류·진행 알림(progress)·취소(cancelled)·서버의 질문(elicitation)·샘플링·roots·로그·구독 알림·작업(tasks) 확장 모두 해당한다. 요청 번호(id)도 바꾸지 않는다. 안내원 자신의 내부 요청은 `iris-relay-<무작위>-n` 번호를 써서 섞이지 않게 한다.
- **켜는 중 취소:** 아직 넘기지 않은 요청이 취소되면 줄에서 빼고 실제 MCP에 보내지 않는다.
- **초기화:** 실제 MCP를 켤 때 클라이언트가 처음 보낸 `initialize` 내용(능력·클라이언트 정보·규격 판)을 그대로 써서 초기화한다. 그래서 서버는 진짜 클라이언트를 상대하는 것과 같은 조건이 된다.
- **새 규격(2026-07-28) 탐색:** `server/discover`에는 "모르는 메서드"(-32601)로 답해 기존 방식으로 넘어가게 한다.
- **오류 구분:** 안내원이 만든 오류는 `[IRIS MCP 중계기]`로 시작하고 `data`에 `{relay:true, server, stage, recoverable, executed}`를 담는다. 실제 MCP가 낸 도구 오류는 손대지 않고 그대로 넘긴다.

| 경우 | 단계(stage) | 요청 실행됨? | 다음 요청 |
|---|---|---|---|
| 실행 파일 없음·시작 실패 | `spawn` | **아니오** | 5초 뒤부터 다시 켜 봄 |
| 초기화 응답 없음(시간 초과)·초기화 오류 | `initialize` | 아니오 | 같음 |
| 작업 도중 실제 MCP 종료 | `running` | **모름** — 자동 재실행 안 함 | 다음 요청은 "상태(열린 문서 등)가 초기화됩니다" 안내 오류 1회 → 그다음부터 새로 켬 |

- **자동 재실행 금지:** 연결이 끊긴 요청을 다시 보내지 않는다. 문서 수정·발송이 두 번 일어나지 않게 하기 위해서다.
- **원인 안내:** 오류 문장에 서버 이름, 실패 단계, 복구 가능 여부, 할 일(`relay.py status`/복구 명령)을 쓴다. 비밀값은 쓰지 않는다. 실제 MCP의 stderr 마지막 30줄은 기록 파일에만 남기며, 그때 환경변수 값과 같은 문자열·긴 토큰 모양 문자열을 가린다.

## 5. 조각 5 — 권한·승인 보존과 직접 연결 전환

- **이름이 같으면 권한도 같다:**
  - 클로드 권한 규칙(`mcp__hwp-automation__*` 등)은 이름으로 걸리므로 그대로 맞는다.
  - 코덱스의 서버별 승인(`default_tools_approval_mode`·`tools.<도구>.approval_mode`·`enabled_tools`·`disabled_tools`)은 같은 블록에 그대로 남는다.
  - 메뉴판이 도구 주석(`readOnlyHint`·`destructiveHint` 등)과 `_meta`를 원문 그대로 보존하므로, 주석에 따라 승인을 묻는 동작도 같다.
- **승인 우회 없음:** 안내원은 도구를 하나로 묶지 않는다. 클라이언트는 원래 도구 하나하나를 보고, 원래 규칙대로 승인을 묻는다.
- **같은 MCP 두 번 실행 방지:** 직접 항목을 **그 자리에서** 안내원 항목으로 바꾼다(항목을 새로 더하지 않는다). 그래서 한 설정 범위 안에 같은 이름이 두 개 생기지 않는다. 전환 뒤 sync가 "같은 이름이 직접 연결로도 다시 생겼는지"를 검사한다(`claude mcp add`로 다시 더한 경우 = 사용자 의도 → 그 새 명령을 등록부로 옮겨 다시 전환한다).
- **직접 연결로 되돌리기(`relay.py restore`):**
  - 등록부에 남긴 원문으로 `command`·`args`를 되돌린다.
  - 사용자가 그 사이 바꾼 항목(안내원 모양이 아닌 항목)은 건드리지 않는다.
  - 서버 하나(`--id`) 또는 전부(`--all`)를 되돌릴 수 있다. 되돌린 항목은 등록부에 "해제"로 남아 sync가 다시 전환하지 않는다(`--relay`로 다시 켬).

## 6. 조각 6 — 지원 범위

| 종류 | 예 | 처리 | 이유 |

## 7. 조각 7 — 공용 중계기 수명과 Face 연동

- **역할:** 공용 중계기는 **도구 호출 길 위에 있지 않다.** 안내원은 공용 중계기 없이도 메뉴판 파일과 등록부만으로 일한다. 공용 중계기가 하는 일은 다음 넷이다.
  - ⓐ IRIS 시작 때 sync
  - ⓑ 낡거나 빠진 메뉴판을 하나씩 조사
  - ⓒ 장부 청소(3절)
  - ⓓ 상태 보기(`127.0.0.1:3461` `GET /health`·`GET /status`)
- **시작:** IRIS 실행기(`<이름> Face.cmd`, P03 `handoff.mjs`가 만든다)에 한 줄을 더한다: `pythonw.exe -I <…>\mcp-relay\relay.py daemon`. 업데이터 kick 줄과 같은 방식이다. 실행기가 띄우고 바로 끝나므로, 공용 중계기는 어떤 세션 가계도에도 속하지 않는다. 그래서 Face 창 닫기(v2.97)의 세션 가계도 정리에 휘말리지 않는다.
- **중복 실행 방지:** 포트 3461을 127.0.0.1에만 열어 둔다. 이미 쓰고 있으면 곧바로 끝낸다(`daemon.json`에 PID·시작 시각·끄기 열쇠).
- **끄기:** `relay.py daemon --stop`. `daemon.json`의 PID·시작 시각·명령줄을 확인하고, 열쇠 헤더를 붙인 `POST /shutdown`으로 끈다. 브라우저가 몰래 보내는 요청은 열쇠가 없어 거절된다.
- **장애 시:** 공용 중계기가 죽어도 열린 세션의 MCP는 계속 동작한다. 다음 IRIS 시작 때 다시 뜨며, 그때 장부를 청소한다.
- **Face 연동(코드 변경 없음):**
  - 안내원과 실제 MCP는 **클로드·코덱스 프로세스의 가계도 안**에 있다. 그래서 v2.97 "창 닫기 = 세션 가계도 종료·확인"이 그대로 적용된다.
  - 최소화·새로고침·화면 연결 끊김은 클로드·코덱스 프로세스를 건드리지 않으므로 MCP도 유지된다.
  - 이번 작업은 P02(Face) 파일을 고치지 않는다. 이 PC의 개발용 실행기 `IRIS-Face.cmd`(P02 원본을 직접 띄움)에도 같은 kick 줄을 더한다.
  - Face 화면에 중계기 상태를 보여 주는 일은 남은 과제로 둔다(`/status` 제공).

## 8. 조각 8 — 기술 선택

- **언어 = 파이썬 3.12 표준 라이브러리만.**
  - 동봉 런타임(`_agent\shared\tools\python`)이 있다.
  - 대기 중인 안내원 1개가 실제 RAM 약 7MB다(실측). 같은 일을 node로 하면 약 60MB다(실측).
  - `ctypes`로 Job Object·일시정지 생성·프로세스 시작 시각을 직접 다룬다(pywin32 불필요).
- **재사용:**
  - `tkukushkin/lazy-mcp`(Go, MIT)의 "메뉴판 + 첫 요청 때 켜기 + 이름 유지" 방식을 **참고만** 한다(별 0개·세션 관리 없음·Go 빌드 도구 없음).
  - 이 PC의 `agent_parity_mcp.py`에서 Job Object 사용과 `cmd /c` 인자 처리 방식을 참고한다.
  - 공식 MCP SDK는 쓰지 않는다. 바이트 그대로 넘기는 것이 목적이라 줄 단위 JSON만 다루면 된다.
- **실행:** `python.exe -I relay.py …`. 격리 모드라 사용자의 `PYTHONPATH` 등에 흔들리지 않는다. 진입 파일이 자기 폴더를 `sys.path`에 직접 넣는다.

## 9. 조각 9 — 설치 패키지 편입

- **원본:** P03 `mcp-relay\`(AGENTS.md·CLAUDE.md 포함, 독립 폴더). 설치 사본 `<설치 폴더>\_agent\shared\tools\mcp-relay\`(slot 부품 — 업데이트 때 `.prev`로 옮기고 새로 놓음). 상태 `<설치 폴더>\_agent\shared\mcp-relay\`(사용자 자료 — 업데이트·재설치에도 보존).
- **잠금표:** 부품 `mcp-relay` = `kind: dir`, `source: ./mcp-relay`, `file: mcp-relay/iris-mcp-relay.zip`, `dest: _agent/shared/tools/mcp-relay`, MIT. updater와 같은 모양이다. 수집·지문·꾸러미 목록·정적 검사·재현 검사는 기존 dir 부품 규칙을 탄다.
- **설치(새 PC):**
  - 풀기 단계가 부품을 놓고, 검증기가 `relay.py`와 판 표시를 확인한다.
  - 연결부(adapters) 단계는 문서 MCP 5종·플레이라이트를 **안내원 항목**으로 쓰고 등록부를 만든다. 등록부의 `owner` = `installer`이고, self-improve는 직접 유지한다.
  - 이어서 `relay.py survey`를 최대 90초 안에서 돌려 메뉴판을 만든다. 실패해도 설치는 실패가 아니며, 첫 세션이 자가 복구한다.
- **업데이트(기존 판 위 `--auto`):**
  - `adapters`는 늘 다시 돈다. 설치기 소유 항목(직접 항목이든 안내원 항목이든 명령이 `_agent\shared\tools` 아래)을 안내원 항목으로 바꾸고, 새 판 경로로 등록부를 고친다.
  - 사용자가 손수 넣은 항목은 설치기가 건드리지 않는다. 공용 중계기의 sync가 다룬다.
  - `mcp-relay`를 `RELAY_PARTS`에 넣어, 이 부품이 바뀌면 실행기에 kick 줄이 다시 쓰이게 한다.
- **IRIS 시작:** 실행기 kick 줄(7절).
- **삭제:**
  - 삭제기는 이미 "설치 폴더 아래 실행 파일로 도는 모든 프로그램"을 PID로 끈다. 동봉 pythonw로 도는 공용 중계기와 안내원도 여기에 포함된다.
  - 설정 파일이 설치 폴더 안에 있으므로 밖에 남는 흔적은 없다. 시험으로 확인한다.
- **장애 복구:**
  - ⓐ `relay.py restore --all` → 모든 항목을 직접 연결로 되돌린다.
  - ⓑ 파이썬조차 안 되면 `…\mcp-relay\backups\<시각>\`의 설정 복구본을 문서의 절차대로 되돌린다.
  - ⓒ 설치기 `--auto` 재실행은 설치기 소유 항목을 다시 맞춘다.
- **영수증:** `installed['mcp-relay']`에 판·지문을 기록한다(기존 부품 규칙).

## 11. 조각 11 — 이 PC 적용

1. 복구본: `.claude.json`·각 `.mcp.json`·코덱스 `config.toml`(전역·역할별)을 `…\mcp-relay\backups\<시각>\`에 복사한다.
2. `relay.py sync --apply`: 대상 항목만 바꾼다. 클로드 전역 stdio 11개·역할/프로젝트 `.mcp.json` stdio 항목, 코덱스 전역·역할별 stdio 항목(이 PC는 기존 중간 실행기 명령을 그대로 "실제 명령"으로 등록 — 비밀 주입·범위 보호가 유지된다).
3. `relay.py survey`로 메뉴판을 만들고, 공용 중계기를 띄운다.
4. **열려 있는 세션은 그대로 둔다** — 지금 세션은 옛 직접 연결로 끝까지 간다. 새로 연 세션부터 적용된다.
5. 실패하면 `relay.py restore --all`로 되돌린다.

| 9 | Popen이 스레드 핸들을 닫아 일시정지 재개 불가 | 재개는 프로세스 핸들로 하는 `NtResumeProcess`라 스레드 핸들이 필요 없다(반영 불필요 — 시험으로 확인). Job 핸들은 상속되지 않게 만든다(보안 속성 없음). Popen `close_fds` 기본값이 표준 입출력 외 상속을 막는다 |
| 10 | 묶음이 일부러 떼어 낸 앱까지 끔 | `JOB_OBJECT_LIMIT_BREAKAWAY_OK`를 켜서 스스로 떼어 내는 앱은 살아남게 한다. 기본 동작은 클로드·코덱스가 지금 하는 가계도 정리와 같다 |
| 11 | 서버가 죽으면 대기 중 요청이 30분을 기다림 | 죽는 즉시 대기 중 요청 전부에 "결과 모름·자동 재실행 안 함·상태 초기화" 오류를 보낸다. 다음 요청은 바로 새로 켠다. 대기 중 요청이 하나도 없었다면 다음 요청에 안내 오류를 1회 보낸다. 죽은 서버에게 가는 클라이언트 답장은 버린다 |
| 12 | 업데이트 때 실행 중 파이썬 잠김·삭제 뒤 남는 항목 | 파이썬 잠김은 지금의 문서 MCP와 같은 조건이다(새 문제 아님 — 기록). 삭제기가 지우기 전에 `restore --all`을 최선 노력으로 돌린다(보관되는 사용자 폴더의 `.mcp.json` 대비) |
| 13 | 페이지 넘김·동적 목록·묶음 요청·출력 오염 | 조사 때 `nextCursor`를 끝까지 따라가고, 응답은 한 페이지로 준다. 리소스·프롬프트 목록은 "조사 시점 사본"이며 켠 뒤 다르면 `list_changed`를 보낸다(한계로 기록). 켜기 전에 들어온 묶음(batch) 요청은 켠 뒤 넘긴다. 표준 출력에는 프로토콜만 쓴다 |
| 14 | 가계도 정리의 PID 재사용·상태 창구 노출 | 자식은 "부모보다 늦게 시작한 것"만 인정한다. 장부 청소는 안내원·실제 MCP 모두 시작 시각까지 비교한다. 상태 창구는 Host 헤더가 `127.0.0.1:3461`일 때만 답하고, CORS 헤더를 주지 않는다 |
