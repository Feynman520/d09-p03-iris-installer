# 설계 — 안정판·최신판 두 갈래 배포 (2026-11-09)

사용자 결정(2026-11-09): 지금 `iris-workspace.com` 에 올라 있는 판(설치 패키지 2.0.55 · IRIS 창 2.99.0)이 **안정판**이다.
앞으로 내는 모든 판은 먼저 **최신판**으로만 나가고, 사용자가 학교 PC 에서 시험한 뒤 안정판으로 올린다.
최신판은 **홈페이지에서만** 받는다. IRIS 안의 「업데이트」는 **안정판만** 받는다. 안정판으로 올리는 결정은 사용자만 한다.

## 0. 지금 구조에서 확인한 사실

| 받는 길 | 무엇을 보나 | 근거 |
|---|---|---|
| IRIS 창 업데이트기(P01 `daemon/update.mjs`) | GitHub `releases/latest`(창·구조판 저장소). 막히면 미러 `latest.json` | `GH()` 25행, 239~255행 |
| 홈페이지 단추(P07 `site/site.js`) | GitHub `releases/latest`. 막히면 `CONFIG.fallback` | 274행, 17행 |
| 미러 `latest.json` | 릴리스 도구 `mirrorLatest()`·P02 `build/mirror-upload.mjs updateLatest()` 가 매 릴리스 갱신 | |

GitHub `releases/latest` 는 **사전 공개(prerelease)·초안을 빼고** 가장 최근 정식 판을 준다. 따라서
① 새 판을 prerelease 로 만들고 ② `latest.json` 을 건드리지 않으면, **이미 깔린 모든 IRIS 창은 코드 변경 없이 안정판만 받는다.**

## 1. 조각

### 1-1. 릴리스 도구 `iris-release.mjs` (창·메신저·설치 패키지 공통)
- `--channel latest|stable` 을 새로 둔다. **기본값 = latest**(잊어도 안전한 쪽).
- latest 일 때:
  - `gh release create … --prerelease` (`--latest` 를 붙이지 않는다). 기존 릴리스 갱신 길(`gh release edit`)도 `--prerelease`.
  - 미러 업로드는 한다(홈페이지 최신판 단추가 미러를 쓴다). **`latest.json` 은 갱신하지 않는다.**
  - 홈페이지는 `CONFIG.fallback`(안정판) 대신 새 블록 `CONFIG.preview` 의 그 부품 값을 고친다.
  - `CONFIG.mirror.assets` 는 **덧붙인다**(지금 도구는 목록을 새 이름 하나로 바꾼다 → 안정판 zip 이 목록에서 빠져 안정판 단추가 GitHub 첨부로 바뀌는 문제. 덧붙이기로 고친다).
- stable(직접 안정판으로 내기)은 지금 동작 그대로 남기되, 쓰려면 `--channel stable` 을 명시해야 한다.
- 새 하위 명령 `promote <face|messenger|installer> <X.Y.Z> [--yes]` — 최신판을 안정판으로 올린다.
  - 문 앞 검사: 그 태그의 릴리스가 있고 **prerelease 상태**이고, 첨부(zip·`.sha256`, 창·설치 패키지는 `.sha256.sig` 까지)가 다 있고, 미러 두 곳(r2.dev·빠른 창구)이 같은 크기로 200 을 주고, 그 판이 지금 안정판보다 높다.
  - `--yes` 없으면 계획만 보인다.
  - 실행: `gh release edit <tag> --prerelease=false --latest` → `latest.json` 그 부품 항목 갱신(값은 릴리스 첨부에서 읽음) → 홈페이지 `CONFIG.fallback[part]` 를 그 판 값으로, `CONFIG.preview[part]` 는 비움 → `index.html` 정적 href 를 그 판 미러 주소로 → 홈페이지 커밋·푸시.
  - 설치 패키지와 창은 **함께** 올리는 것이 원칙(구조판에 창이 들어 있다). 명령은 부품별이지만, 설치 패키지를 올릴 때 같은 날 낸 창 최신판이 남아 있으면 경고한다.
- 값은 사람이 적지 않는다: 크기·이름은 GitHub 릴리스 첨부에서, sha256 은 `.sha256` 첨부 내용에서 읽는다.

### 1-2. 설치 패키지를 손으로 낼 때(행렬 S01~S11 이 안 찬 지금의 수동 길)
- `gh release create <tag> … --prerelease`.
- `build/mirror-upload.mjs` 는 지금 zip 을 올리면 `latest.json` 을 **자동 갱신**한다 → 기본값을 **갱신 안 함**으로 바꾸고, 갱신은 `--stable` 을 명시했을 때만.
- 홈페이지는 `iris-release.mjs preview-homepage installer <X.Y.Z>`(새 하위 명령, 값은 릴리스에서 읽음)로 `CONFIG.preview` 를 채운다.

### 1-3. 홈페이지 (P07)
- `CONFIG.fallback` = 안정판(뜻 그대로). 새 `CONFIG.preview = { installer: {...} | null, face: {...} | null }`.
- 내려받기 절: 지금 단추 = **「안정판 (권장)」**. 그 아래에 **「최신판 (시험 중)」** 상자 — `preview.installer` 가 있고 그 판이 안정판보다 높을 때만 보인다. 없으면 상자를 숨긴다.
- GitHub API 로 `releases?per_page=10` 을 한 번 더 읽어, 안정판보다 높은 가장 최근 prerelease 가 있으면 그 값으로 덮는다(sha 값은 `CONFIG.preview` 와 판이 같을 때만 보인다). API 가 막히면 `CONFIG.preview` 그대로.
- 최신판 상자 안내: 새 기능을 먼저 써 보는 판 · IRIS 안 「업데이트」로는 오지 않음 · **최신판을 깐 PC 를 안정판으로 되돌리려면 삭제 후 안정판을 새로 설치**(설치기는 같거나 낮은 판으로 「업데이트」를 제안하지 않는다 — `server.mjs wizardUpdateOffer()` `cmpVer(from, version) >= 0` 이면 null).
- 「구성 요소와 새 소식」 절은 안정판 그대로.

### 1-4. 설치된 PC 에서의 흐름
- 안정판 PC: 업데이트 버튼은 안정판만 봄(변경 없음).
- 최신판을 홈페이지에서 깐 PC: 업데이트기가 보는 안정판이 더 낮으므로 업데이트 없음 → 그 판이 안정판으로 올라가거나 더 높은 안정판이 나오면 그때 받는다.

## 1-5. 코덱스 독립 설계 검토(2026-11-09) 반영 — 지적 12건

| # | 지적 | 처리 |
|---|---|---|
| 1 | 안정판 격리는 GitHub 말고도 미러 `latest.json` 에 달림 | 반영: `latest.json` 은 안정판 전용. 쓰는 길 둘(`iris-release.mjs mirrorLatest`·`mirror-upload.mjs`) 모두 최신판에선 안 씀. 창 업데이트기도 사전 공개·초안 응답을 버리고 `latest.json` 으로 감(이중 안전장치, `verify:update` 7b) |
| 2 | 설치 패키지만 올리면 안의 창이 시험 안 된 판일 수 있음 | 반영: `promote` 가 설치 패키지 zip 안 `payload/face/iris-face.zip` 의 `package.json` 판을 읽어, 함께 올리는 창 판(없으면 지금 안정판 창 판)과 다르면 **거절**(`bundleVerdict`) |
| 3 | 올리다 중간 실패하면 다시 실행이 막힘 | 반영: 이미 정식이고 안정판 포인터인 릴리스는 "남은 단계만 마저 함"으로 통과, 단계마다 같은 결과면 건너뜀, 끝에 공개 경로를 다시 읽어 확인 |
| 4 | 같은 태그 덮어쓰기가 채널·검증을 무너뜨림 | 반영: `reuseVerdict` — 정식 태그를 최신판으로 되돌리지 않고, 해시가 다르면 덮지 않음(판을 올려야 함) |
| 5 | `latest.json` 읽기 실패 때 빈 표로 덮음 | 반영: 404 만 빈 표, 그 밖의 실패는 멈춤(두 도구 모두). 동시 실행은 사람 한 명이 손으로 내므로 다루지 않음 |
| 6 | "삭제 후 안정판 새로 설치"가 입증 안 됨 | 부분 반영: 문구를 「삭제(내 작업 보관) → 안정판 새로 설치」로 못박음. 새로 설치는 e2e 가 매 판 시험하는 길이고, 낮은 판을 같은 폴더 위에 얹는 "되돌리기"는 지원하지 않음(설치기가 업데이트를 제안하지 않음) |
| 7 | 창의 서명 형식이 설치 패키지와 다름 | 반영: 부품별로 — 설치 패키지 = `.sha256.sig`, 창 = zip 안 manifest 서명(`inspectZipFile`) |
| 8 | 200·크기만으로 동일성 증명 불가 | 반영: GitHub·r2.dev·빠른 창구의 `.sha256` 글자 일치 + 빠른 창구 zip 을 끝까지 받아 계산한 해시 일치 |
| 9 | 홈페이지 fallback 의 url·page 미갱신, 정적 HTML 크기 불일치 | 반영: url·page 도 갱신, 정적 `index.html` 의 주소·판·크기·날짜·해시를 함께 갱신(`setStaticInstallerHtml`), 옛 541,021,818 값 수정 |
| 10 | 최신판 자동 탐색의 호출 한도·버전 규칙 | 반영: 최신판은 **API 로 찾지 않고** `CONFIG.preview`(사람이 낸 값)만 그림. 판은 X.Y.Z 세 정수만, 숫자 비교 |
| 11 | 같은 판이란 이유만으로 해시 표시 | 반영: 판 **과 첨부 이름**이 같을 때만 안정판 해시 표시, 최신판 해시는 그 판 값만 |

## 2. 시험(무회귀 원칙 3)
- 릴리스 도구: `--channel` 기본값 latest · latest 일 때 gh 인자에 `--prerelease` 있고 `--latest` 없음 · latest.json 안 건드림 · 미러 목록 덧붙이기 · promote 문 앞 검사(정식 판·첨부 빠짐·미러 크기 다름이면 거부) — gh·미러는 가짜로.
- mirror-upload: 기본 = latest.json 안 건드림, `--stable` 일 때만.
- 홈페이지: headless 브라우저로 ① preview 없음 → 최신판 상자 숨김 ② preview 판 > 안정판 → 상자·단추 주소·판 표시 ③ API 막힘 → CONFIG 로 그림 ④ preview 판 ≤ 안정판 → 숨김.
- 실측: 첫 최신판(판 A)을 낸 뒤 `releases/latest` 가 여전히 2.0.55 / 창 2.99.0 인지, `latest.json` 이 그대로인지, 홈페이지 두 단추가 각 판을 가리키는지 확인.
