# IRIS 설치 패키지 설계 v1 (2026-09-10, 사용자 확정 조각 ①~⑥ 통합)

> 상태: 명세 초안 — 사용자 검토 대기. 확정되면 `docs\구현계획.md`로 이어진다.
> 만든 사람: 함세준 · 허가서: MIT · 패키지 이름: IRIS (2026-09-10 결정, P02 구현계획 v2.27과 동일)

## 0. 목표와 불변 원칙

**목표 한 줄.** 아무것도 설치되지 않은 보통 윈도우 PC를 가진 사람이 **zip 하나를 받아 두 번 클릭**하면, 사람만 할 수 있는 **구독 로그인 한 번**을 빼고 IRIS 체계 전체가 끝까지 설치된다. 그 뒤로는 IRIS-Face 아이콘만 누른다.

**왜 만드나.** 지금까지는 연수·책으로 터미널을 열어 에이전트를 설치하게 했다. 컴퓨터마다 윈도우 버전·winget 유무·실행 정책·기존 Node·백신·권한이 달라 같은 명령이 어떤 PC에서는 되고 어떤 PC에서는 안 됐다. 원인의 공통점은 "그 컴퓨터에 이미 있는 것에 의존했다"는 것이다. 이 패키지는 필요한 것을 전부 갖고 가서 그 의존을 없앤다.

**불변 원칙.**
1. **사용자 수동 단계 0.** 어디 들어가서 무엇을 내려받거나 명령을 치는 일이 없다. 예외는 브라우저 구독 로그인 하나.
2. **완전 동봉.** 설치기가 인터넷에 기대는 순간은 로그인(과 6-3의 Claude Code 예외)만. 나머지 부품은 zip 안에 있다.
3. **자급자족.** 컴퓨터에 이미 있는 Node·Python·Git·winget·관리자 권한에 의존하지 않는다. 동봉 런타임을 `_agent\shared\tools`에 두고 거기서만 실행한다.
4. **지우지 않는다.** 기존 폴더·기존 프로그램·사용자 자료를 삭제·덮어쓰지 않는다. 부품 교체는 `_agent\shared\tools` 안에서만, 이전 판은 `.prev`로 보존.
5. **재실행 안전.** 중간에 꺼져도 다시 실행하면 영수증을 읽고 끝난 단계는 건너뛴다.
6. **프로세스 종료는 PID로만.** 이름 기반 일괄 종료 금지(루트 규칙).
7. **비밀은 만지지 않는다.** 토큰은 TeamClaude가 자기 자리에 쓰고, 설치기·영수증·로그에는 들어가지 않는다.
8. **zip을 손으로 고치지 않는다.** 원본 수정 → 재빌드 → 검사소 통과 → 새 버전 이름.
9. **부품 잠금.** 모든 부품은 버전·SHA-256으로 잠근다. `latest`·`main`·무버전 `npx` 금지(세팅가이드 8-6절과 동일).
10. **TeamClaude 항상 경유.** 계정 수와 상관없이 에이전트는 TeamClaude 프록시(127.0.0.1:3456)를 거친다(사용자 결정 2026-09-10).

**정직한 한계(설치기가 첫 화면에서 미리 검사해 알린다).**
- Windows 10 1809 이상 또는 11, 64비트(32비트·Windows 7·8은 Node 24가 돌지 않음).
- 로그인 순간의 인터넷: `claude.ai`·`chatgpt.com`이 열려야 한다. 이를 막는 회사망은 방법이 없다.
- 디스크 여유 2GB.
- 그 외 관리자 권한·기존 Node·백신·실행 정책·PATH 문제는 자급자족으로 우회된다.

## 2. 조각 ① — 패키지 내용물과 설치 후 구조

### 2-1. zip 안 (보내는 것)

```text
IRIS-설치.zip                      ← 전달 파일 1개 (압축 300MB대)
├ IRIS-설치.cmd                    ← 사용자가 두 번 클릭하는 유일한 파일 (UTF-8 + chcp 65001)
├ installer\
│  ├ bootstrap.ps1                 ← 1단: 무결성 검사 → Node 풀기 → 설치기 서버 켜기 (PowerShell 5.1, UTF-8 BOM)
│  ├ server.mjs                    ← 2단: 127.0.0.1:3460 웹 화면 서버 + 설치 작업 (동봉 Node)
│  ├ lib\manifest.mjs              ← 지문 계산·검증 (빌드 도구와 같은 파일)
│  └ ui\index.html                 ← 설치 화면 (단일 HTML, Face style.css의 색·글꼴 변수 블록 복사)
└ payload\
   ├ manifest.json                 ← 모든 부품의 이름·버전·SHA-256 (무결성 검사 기준)
   ├ node\      node-v24.x-win-x64.zip
   ├ agents\    claude-code-<ver>.tgz · codex-<ver>.tgz         ← npm pack 원본 (설치 = 풀기) ※ Claude Code는 6-3 참조
   ├ relay\     teamclaude-<ver>+iris.tgz                        ← 로컬 패치 4파일 적용본
   ├ face\      iris-face-<ver>.zip                              ← node_modules(Electron·node-pty·xterm) 포함
   ├ dash\      teamclaude-dash\
   ├ python\    python-3.12.x-embed-amd64.zip + PyYAML-<ver>.whl
   ├ git\       MinGit-2.54.x-64-bit.zip
   ├ guides\    세팅가이드(Claude 실행판)_v10.md · 세팅가이드(Codex 실행판)_v10.md
   └ licenses\  부품별 허가서 사본
```

`manifest.json`의 지문이 실제 파일과 다르면 설치기는 시작 전에 "파일이 손상됐습니다. 다시 받아 주세요"로 멈춘다.

### 2-2. 설치 후 (받는 사람의 컴퓨터) — 세팅가이드 6절 표준 구조를 그대로 따른다

```text
C:\<영혼 이름>\
├ AGENTS.md · CLAUDE.md               ← 가이드가 만든다
├ soul-state.json                      ← 설치기가 최소 표지로 먼저 씀 → 가이드가 채움
├ <영혼> Face.cmd                      ← 루트 소환기 (바탕화면 .lnk가 가리킴)
├ _setup-guides\ 두 판                  ← 에이전트가 읽는 계약서 (잠든 에이전트를 깨울 때도 필요)
└ _agent\
   ├ claude\  codex\                   ← CLAUDE_CONFIG_DIR · CODEX_HOME (가이드 2-2절)
   ├ setup\   package-receipt.json · package-install.log
   ├ shared\tools\  node\ python\ git\ claude\ codex\ teamclaude\ teamclaude-dash\ iris-face\
   ├ shared\shims\  claude.cmd · codex.cmd · node.cmd   ← 사용자 PATH에 이 폴더 1개만 추가(관리자 불필요)
   ├ shared\portable-state\teamclaude\ ← 프록시 설정(가능하면; 안 되면 runtime\hosts\…\exceptions.json에 기록)
   └ runtime\hosts\<host-id>\          ← 기계마다 다른 상태
```

- 선택하지 않은 에이전트도 파일은 놓인다(잠듦). `shims`에는 **로그인된 에이전트의 .cmd만** 만들고, 깨울 때 추가한다.
- 이 PC(`<IRIS 루트>`)의 Face·대시보드 위치는 바꾸지 않는다. 빌드 도구가 복사할 때 자리를 바꿔 넣는다.
- 영혼 이름의 한글 허용 여부는 node-pty 실측(8절 ①) 뒤 결정. 실패하면 영문·숫자만.

## 3. 조각 ② — 설치기의 흐름과 화면

### 3-1. 두 겹 구조

겉옷(`.cmd` + `bootstrap.ps1`)은 아무것도 없는 윈도우에서도 도는 최소한만 하고, 속옷(`server.mjs` + 웹 화면)은 동봉 Node 위에서 진짜 일을 한다. PowerShell 몫을 최소화하는 이유 = 한글·인코딩 함정(R-004·R-008·R-010).

### 3-2. 겉옷 — `bootstrap.ps1` (10~20초)

```text
① 위치 확인 — zip 안(임시 폴더)에서 실행했으면 "먼저 압축을 풀어 주세요"
② 무결성 — manifest.json ↔ payload 파일 SHA-256. 다르면 중단
③ 임시 자리 — %LOCALAPPDATA%\IRIS-Installer\ 에 Node만 풀기 (영혼 이름을 모르므로 C:\ 아래엔 아무것도 안 씀)
④ 서버 켜기 — 동봉 node로 installer\server.mjs, 127.0.0.1:3460 준비 확인
⑤ 브라우저 열기 — 기본 브라우저. 검은 창은 최소화("이 창을 닫지 마세요")
```

호출은 `powershell -NoProfile -ExecutionPolicy Bypass -File`이라 실행 정책 문제가 없다. Mark-of-the-Web(인터넷에서 받은 파일 표식)은 ⓓ 복사 단계에서 풀린 파일에 `Unblock-File`로 제거한다(관리자 불필요) — `electron.exe`·`node.exe` 첫 실행 SmartScreen 경고 예방.

### 3-3. 속옷 — 화면 6장 (단일 HTML 마법사, 위 진행 바 + 현재 단계 카드, 새로고침해도 같은 단계)

| 단계 | 화면 | 뒤에서 | 다음 조건 |
|---|---|---|---|
| ⓐ 사전검사 | 체크 3개 ✓/✗ + 실패 이유·할 일 | OS 버전·64비트·여유 공간·`claude.ai`/`chatgpt.com` 도달·기본 브라우저 존재 | 전부 ✓ (인터넷만 ✗면 ⓓ까지 진행 허용) |
| ⓑ 영혼 이름 | 입력 1개 + `C:\NOVA` 미리보기 + 금지 이유 즉시 표시 | 가이드 2-1절 규칙(금지 문자·예약 이름·시스템 폴더·reparse point·NTFS) | 유효 이름. 폴더가 이미 있고 `soul-state.json`이 있으면 "기존 영혼 → 이어서(권장)/다른 이름" 분기(4-6) |
| ⓒ 구독 선택 | ☐ Claude ☐ ChatGPT + 한 줄 설명 | 주도 에이전트·가이드 판 결정 | 1개 이상. 0개면 구독 안내 화면(설치 안 함) |
| ⓓ 복사 | 부품별 프로그레스바 | payload → `_agent\shared\tools` 풀기 · shims · 사용자 PATH · 최소 `soul-state.json` · 영수증 · MOTW 제거 | 전 부품 검증(파일 수·실행 파일 존재·`node -v`·`python -V`·`git --version`·`claude --version`) |
| ⓔ 로그인 | 계정별 카드 "[Claude 로그인] 새 창이 열립니다 → 브라우저에서 로그인 후 돌아오세요" + 상태 | **구독별 CLI 자체 로그인 1회**(`claude`/`codex`를 프록시 변수 없는 별도 콘솔에서 로그인만) → 인증 파일 생성 감지 → TeamClaude가 그 파일에서 계정 가져오기(불가하면 `teamclaude login` 1회 추가) → 상태 폴링 (실측 2026-09-11, 10절 #1) | 선택한 구독 전부 `cli`·`relay` 완료 |
| ⓕ 완료 | "설치가 끝났습니다. 이제 비서가 이어받습니다" + [Face 열기](3초 뒤 자동) + "보안 프로그램이 물으면 허용" | Face 실행(첫 세션 인자) → 데몬 응답·세션 1개 확인 → 영수증 handoff=done → 설치기 종료·임시 폴더 정리 → 바탕화면 바로가기 | Face 데몬 응답 |

- 설치기는 **이름·구독·로그인 3가지만 묻는다.** R/D/P/S/T 구조·아이콘 질문(가이드 5절)은 에이전트 몫이다(같은 질문을 두 번 받지 않게).
- 화면 문구에 TeamClaude라는 이름을 쓰지 않는다("Claude 계정 로그인"). 중계기 이름은 대시보드에서만.
- 회사망이 OAuth를 막으면 ⓔ에서 정확히 알리고 설치는 남긴다. 재실행 시 ⓔ로 바로 간다.
- 로그 = `_agent\setup\package-install.log` 하나(단계·시각·결과, 비밀 없음).

## 4. 조각 ③ — 인수인계: 영수증·최소 표지·첫 요청문·가이드 v10

### 4-1. 설치기가 남기는 세 가지

**① 영수증 `_agent\setup\package-receipt.json`** (schema 1)

```json
{
  "schema": 1,
  "package": { "name": "IRIS", "version": "1.0.0", "built": "2026-09-xx", "guideVersion": "10", "license": "MIT" },
  "soul": { "root": "C:\\NOVA", "name": "NOVA", "createdBy": "package-installer" },
  "choice": { "subscriptions": ["claude", "chatgpt"], "leadAgent": "claude", "guideEdition": "claude" },
  "installed": {
    "node": { "version": "24.x.y", "path": "_agent\\shared\\tools\\node", "sha256": "…", "verified": true },
    "python": { "version": "3.12.x", "path": "…", "verified": true },
    "git": { "version": "2.54.x", "path": "…", "verified": true },
    "claude": { "version": "…", "path": "…", "verified": true, "active": true, "source": "bundled|npm-registry" },
    "codex": { "version": "…", "path": "…", "verified": true, "active": true },
    "teamclaude": { "version": "1.1.16+iris4", "patches": ["server.js", "activity.js", "codex-quota.js", "account-manager.js"], "verified": true },
    "teamclaude-dash": { "verified": true },
    "iris-face": { "version": "2.xx.0", "verified": true }
  },
  "login": { "claude": { "done": true, "at": "…" }, "chatgpt": { "done": true, "at": "…" } },
  "env": { "CLAUDE_CONFIG_DIR": "C:\\NOVA\\_agent\\claude", "CODEX_HOME": "C:\\NOVA\\_agent\\codex", "ANTHROPIC_BASE_URL": "http://127.0.0.1:3456", "pathShim": "C:\\NOVA\\_agent\\shared\\shims" },
```

### 6-1. 위치와 언어

이 프로젝트(P03). `installer\` · `build\`(collect·sanitize·manifest·pack·build) · `verify\`(static·reproduce·e2e-checklist.md) · `patches\teamclaude\`(앵커→치환 규칙, 이 PC의 `teamclaude-local-patches-20260907.zip` README에서 옮김) · `lock.json` · `_build\cache\`(내려받은 원본) · `_build\out\`(완성 zip). 언어 = **Node(ESM) 하나** — 설치기·Face·대시보드와 같고, 지문 코드(`lib/manifest.mjs`)를 설치기와 공유한다.

### 6-2. 공장 4단계 `node build/build.mjs`

```text

② 정화(sanitize) — 개인정보·고정경로·비밀파일이 있으면 즉시 중단
③ 지문(manifest) — 전 파일 SHA-256 + 버전표 → manifest.json
④ 포장(pack) — 최대 압축 zip + .sha256. 이름 IRIS-설치_v<패키지버전>_<YYYY-MM-DD>.zip
```

## 8. 조각 ⑥ — 배포·업데이트·첫 공개 순서

### 8-1. 배포 선반

GitHub Pages(홈페이지)는 파일당 100MB 제한 → zip을 못 놓는다. **GitHub Releases**(파일당 2GB, 버전별 고정 주소, `.sha256` 병기)를 주 통로로, 홈페이지에는 `/download` 페이지 하나(항상 최신 릴리스로 연결, 주소 불변). 구글 드라이브는 예비(100MB 초과 시 검사 불가 경고), USB는 연수용 병행(같은 zip, 별도 판 없음). 공개 저장소(MIT, IRIS)에 P03과 P02 소스를 둔다 — 공개 전 정화 규칙을 저장소에도 돌린다.

### 8-2. 새 버전

```text
우리 — 원본 수정 → 빌드 → 검사소 3층 → Release v1.x.0 (zip + .sha256 + 변경 요약)
사용자 — Face 상단 "새 버전" 배지(하루 1회 릴리스 목록 확인, 설정에서 끔 가능, 첫 실행 때 한 줄 고지)
사용자 — 배지 → /download → 새 zip → IRIS-설치.cmd (처음과 같은 동작)
설치기 — "기존 영혼" 분기 → 영수증 버전 비교 → 바뀐 부품만 교체(이전 판 .prev 보존) → 영수증 갱신
```

사용자 자료(R/D/P·기억·설정·시크릿)는 업데이트가 절대 만지지 않는다. Face·프록시 실행 중이면 끄지 않고 "다음 실행부터"로 표시. 에이전트 자체 업데이트는 사용자 규칙(2026-09-10, 자동 업데이트 켬)을 따르되 npm 포터블 설치에서 Claude Code 자체 업데이터가 우리 폴더에 쓸 수 있는지는 실측(안 되면 Face가 `npm update`를 대신 돈다).

### 8-3. 문제 보고

Face 정보창·설치기 실패 화면에 **[문제 보고 파일 만들기]** — 설치 로그·영수증·데몬 로그·버전표를 비밀 없이 zip 하나로 바탕화면에. 대화 내용·토큰·자료는 넣지 않는다.
