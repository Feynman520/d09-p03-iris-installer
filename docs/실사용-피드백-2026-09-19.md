## 2. 이번에 새로 알게 된 것(교훈)

1. **"⑥ 에서 대기로 두고 ⑦ 뒤에 다시 잰다"고 적었으면 실제로 다시 재는 코드가 있어야 한다.** 2.0.18 의 검사 12/13 대기 처리는 "다음에 다시 잼"이라고만 적고 그 자리를 만들지 않았다. 대기 판정을 두는 검사는 **재측정 지점**(이번엔 `/api/online/relay` 성공 직후)을 같은 턴에 만들고 시험으로 못 박는다.
2. **부품이 "있다"는 검사는 실행 파일까지 봐야 한다.** face 부품은 `npm ci` 가 성공했다는 것만 믿었고 `electron.exe` 는 아무도 안 봤다. 정적 검사 ⑳ 으로 `electron.exe` 존재를 못 박았다(아래 3절).
3. **v1 → v2 이식 때 빠진 호출은 시험이 잡지 못했다.** `firstrun.test.mjs` 는 헬퍼만 시험했고 "엔진이 그것을 부른다"는 시험이 없었다 — adapters 시험에 결과 파일 assert 를 더했다.
4. **키 입력은 한 덩어리로 쓰지 않는다.** 코덱스 "Update available" 자동 응답이 이미 200ms 로 나눠 쓰고 있었는데 확인 카드는 그 교훈을 안 물려받았다.

- **집 데스크탑(코덱스만)에서 2.0.20 으로 다시 설치** → ⑦ 화면에 "검사 13 중계기 경유(코덱스…) 통과 · CA 번들 갱신" 행이 보이는지 → 코덱스 세션 한 번 → 대시보드 활동 표시. 안 되면 ⑦ 카드의 「개발자에게 신고하기」로 보내면 묶음이 이쪽으로 온다.
- 첫 세션에서 신뢰 물음·샌드박스 물음이 **안 뜨는지**, 떠도 카드 클릭이 먹는지.

- 메신저 말풍선 폭(0.4.3 은 설치 패키지 동봉 + IRIS 창 「업데이트」로도 옴).
