# 세팅 엔진 모듈 계약 v2 (`installer/setup/*.mjs`, T13~T18 공용)

엔진(`setup/engine.mjs`)은 아래 단계 모듈을 **순서대로** 부른다. 각 단계 모듈은 같은 모양의 함수를 export 한다. 모듈끼리 서로 import 하지 않는다(공용 헬퍼는 `installer/lib/`에).

## 단계 id와 모듈

| 순서 | id | 모듈 | 하는 일 | 오류 코드 |
|---|---|---|---|---|
| 1 | `unpack` | `setup/unpack.mjs` | 부품 풀기(기존 `lib/install.mjs` 재사용) · MotW 제거 | `E-UNPACK` |
| 2 | `env` | `setup/unpack.mjs` (export `runEnv`) | shims · 사용자 PATH · `CLAUDE_CONFIG_DIR`·`CODEX_HOME`·`ANTHROPIC_BASE_URL` (기존 `lib/shims.mjs`·`lib/userpath.mjs`) | `E-ENV` |
| 3 | `skeleton` | `setup/skeleton.mjs` | soul-state · 루트 AGENTS/CLAUDE · `_agent`·`_ontology`·`_trash`·`_cleanup`·`_document-templates` · `_cosmos.ico`+`desktop.ini` · 미니 지침 | `E-SKELETON` |
| 4 | `structure` | `setup/structure.mjs` | `decisions.json` → R/D/P 폴더 + 미니 지침 | `E-STRUCTURE` |
| 5 | `venv` | `setup/venv.mjs` | standalone python + uv 로 `document-mcp` venv(오프라인) · PyYAML을 런타임에 | `E-VENV` |
| 6 | `adapters` | `setup/adapters.mjs` | Claude·Codex 설정(파일만, T03 보고 형식) | `E-ADAPTERS` |
| 7 | `relay` | `setup/relay.mjs` | TeamClaude 설정 뼈대 · 대시보드 바로가기 · `IRIS Face.cmd` · 바탕화면 바로가기 · `소환하기.cmd`(기존 `lib/proxy.mjs`·`lib/handoff.mjs` 재사용; 중계기 **시작은 안 함**) | `E-RELAY` |
| 8 | `ontology` | `setup/ontology.mjs` | `build_graph --init --write` → `--compile` → `validate` → `render_view` → `check_fresh` | `E-ONTOLOGY` |
| 9 | `checks` | `setup/checks.mjs` | 검사 9항목 → `handoff.json`·`설치보고.md`·`diagnostics.json`(`setup/handoff.mjs`·`setup/report.mjs`) | `E-CHECKS` |

⑨ 검사는 자기 차례가 아직 `running`인 채로 인수 문서를 쓰므로 `assumeDone:['checks']`로 "지금 도는 이 단계는 끝난 셈"이라고 알린다. **검사가 하나라도 실패하면 그 가정을 쓰지 않는다**(`assumeDone: []` + `failed`를 그대로 넘김) — 실패한 설치가 `setup.allDone:true`로 적히면 Face가 완료로 읽고 첫 인사를 해 버린다. 실패 시 인수 문서는 `state:'setup-incomplete'`·`setup.allDone:false`·`setup.failed:{id:'checks',code:'E-CHECKS'}`.

## 단계 함수 모양

```js
// 모든 단계 모듈
export const id = 'skeleton';
export async function run(ctx) { /* … */ return { recorded: {...}, pending: [...] }; }
```

`ctx` (엔진이 만들어 넘김, 단계가 바꾸지 않음):

| 필드 | 뜻 |
|---|---|
| `root` | 영혼 루트 절대경로(`C:\IRIS` 또는 연습 루트) |
| `payloadDir` | 풀린 zip의 `payload\` 절대경로 |
| `manifest` · `lock` | `payload\manifest.json` · 포장된 `lock.json`(읽기 전용 객체) |
| `receipt` | 영수증 객체(`lib/receipt.mjs`; 단계는 `ctx.receipt.setup[id]`를 직접 쓰지 않는다 — 엔진이 기록) |
| `decisions` | `decisions.json` 객체(`structure`·`skeleton` 사용) |
| `choice` | `{ subscriptions, leadAgent }` |
| `precheck` | 준비 검사 `recorded`(Edge·SAC·기존 설치 등) |
| `log(line)` | 한 줄 로그(엔진이 `_agent\setup\setup.log`에 모음) |
| `progress({ done, total, label })` | 하위 진행(풀기 부품별 등) |
| `run(exe, args, opts)` | 자식 프로세스 실행 헬퍼(`lib/run.mjs`), 시험에서 가짜로 주입 |
| `fs` | `node:fs` 또는 시험용 가짜(쓰기 경로 검사 포함) |
| `env` | 자식 프로세스용 환경(동봉 node/python/git이 PATH 앞) |
| `offline` | `true`면 네트워크 금지(엔진 단계는 전부 true여야 정상) |
| `toolsDir` | `<root>\_agent\shared\tools` |

반환 `{ recorded, pending }`: `recorded`는 영수증 `setup.<id>.recorded`에 저장되는 작은 JSON(경로·판·개수), `pending`은 `[{ capability, reason }]`(예: `{capability:"문서 자동화(한글)", reason:"한컴오피스 없음"}`) — 엔진이 모아 `handoff.pendingCapabilities`로.

실패는 `throw new StageError(code, message, detail)`(`lib/errors.mjs` 신설; `code`는 위 표의 것, `message`는 사용자에게 보일 한국어 한 문장, `detail`은 로그용). 다른 예외는 엔진이 `E-<ID>`로 감싼다.

## 엔진

```js
export async function runSetup(ctx, { failAt = process.env.IRIS_INSTALLER_FAIL_AT, onStage } = {})
```
- 순서대로 실행. 시작 전 `receipt.setup[id] = { status:'running', startedAt }`, 끝나면 `{ status:'done', finishedAt, recorded }`, 실패면 `{ status:'failed', code, message }` — 매번 원자 저장(`lib/receipt.mjs writeReceipt`).
- 재실행: `status === 'done'`인 단계는 건너뜀(`onStage({id, status:'skipped-done'})`). **건너뛴 단계가 `env`이면 그 단계가 지난번에 남긴 `recorded`에서 자식 환경(PATH·`CLAUDE_CONFIG_DIR` 등)을 되살려 뒤 단계에 물려준다** — 건너뛰었다는 이유로 환경이 사라지면 뒤 단계가 동봉 파이썬 대신 PATH의 아무 파이썬을 보게 된다.
- `failAt === id`면 그 단계 `run` 호출 **직전에** `StageError(code, 'fault injection')`.
- `onStage({ id, status, percent, sub })`를 단계 전환·하위 진행마다 호출(서버가 `GET /api/setup/progress`로 노출).
- 반환 `{ ok, failed?: {id, code, message}, pending: [...] }`.

## 업데이트 모드(`--auto`)

업데이트는 **이 엔진을 한 번 더 도는 것**이다. 옛 v1 `install()` 경로는 2.0에서 폐기됐다(부품 33개 중 12개만 알고, 파이썬을 `strip:0`으로 풀고, 되돌리기가 없었다).

1. 서버(`POST /api/auto`)가 `lib/update-plan.mjs`로 **다시 돌 단계**를 고른다.
   - 언제나: `unpack`(부품 교체) · `env`(심·PATH — 판 폴더 이름이 바뀐다) · `adapters`(설정 안 우리 항목이 새 경로를 가리켜야 한다)
   - 조건부: `venv`(python·uv·`document-mcp-wheelhouse`·pyyaml 중 하나라도 판이 바뀌면) · `relay`(node·face·dash·teamclaude·manage·updater·messenger 중 하나라도 바뀌면 — 실행기·바로가기가 그 경로를 품는다)
   - 그대로 둠: `skeleton`·`structure`·`ontology`·`checks`(그 사람의 영혼 쪽)
   - 부품이 "바뀌었나"는 영수증의 `installed.<부품>`(판·지문) → `setup.unpack.recorded.parts.<부품>.identity` 순으로 보고 잠금표·manifest와 견준다. 견줄 값이 한 쌍도 없으면 **바뀐 것으로** 친다(모르는 채 건너뛰지 않는다).
2. 고른 단계만 `status:'pending'`으로 되돌린다. 옛 기록(`recorded`·`pending`)은 지우지 않고 `resetBy:'auto-update'`·`resetReason`·`resetAt`을 덧붙인다.
3. 마법사와 **같은 ctx**로 `runSetup`을 부른다. `unpack`은 동일 부품을 스스로 건너뛰고(identity), 바뀐 부품만 `<dest>.prev`로 옮긴 뒤 새로 놓는다 — 그래서 "바뀐 것만" 바뀐다.
4. 끝나면 서버가 영수증의 `package`를 새 판으로 고치고 `update:{ from, to, at, reset, changedParts }`를 남긴다. 멈추면 판을 고치지 않는다(멈춘 자리가 그대로 남아 다음 실행이 이어간다).

`adapters`의 **설치기 소유 예외**(업데이트가 실제로 뜻을 갖게 하는 규칙): 명령·경로가 `<root>\_agent\shared\tools` 또는 `<root>\_agent\claude\scripts` 아래(플러그인은 `_agent\claude\plugins\cache\iris-local`)를 가리키는 MCP·훅·플러그인 항목은 **우리가 쓴 것**이므로 새 판 경로로 갱신한다. 그 사람이 더한 키, 그리고 이름은 같아도 다른 곳을 가리키는 항목은 어떤 경우에도 건드리지 않는다.

## 멱등·무삭제 규칙(모든 단계)
- 존재하는 파일·폴더는 **덮지 않는다**. 설치기 소유 파일(shim·`desktop.ini`·`IRIS Face.cmd`·설정 파일의 우리 키)만 갱신하며, 사용자 소유(R/D/P 내용·기존 AGENTS.md 본문·기존 설정의 다른 키)는 건드리지 않는다.
- JSON/TOML 병합은 "없는 키만 추가"(기존 `lib/firstrun.mjs` 방식).
- 쓰기 전 경로는 `root` 아래인지 확인(`lib/paths.mjs` `assertInside(root, p)` 신설). 경로 위의 기존 폴더가 정션·심볼릭 링크(reparse point)이면 밖으로 새어 나갈 수 있으므로 함께 거부한다. 위반은 공용 코드 `E-OUTSIDE-ROOT`(단계 표 밖의 공용 코드; 엔진이 다시 감싸지 않음). 예외 허용 = 사용자 PATH/환경변수(레지스트리), 바탕화면 바로가기 1개.
- 단계는 자기 결과를 두 번 실행해도 같은 결과가 되게 쓴다(시험 항목).
