# 실행 검사소 — 수용 조건 체크리스트 (검사소 3층)

**시험 대상 zip (2026-09-13 배포 전 시나리오 점검, 검증기록 14절):** `_build/out/IRIS-설치_v1.2.0_2026-09-13.zip` · 250,049,096 bytes(약 238.47 MB) · sha256 `c99efcfffcf05f070190c28948a63b2ca71b4ba6595212f9851d0a14f35adb41` · Face 2.57.0 · Claude Code 2.1.270 · 정적 검사 ①~⑨ 전부 통과. **구판(v1.0.0·v1.1.0)으로는 시험하지 않는다** — v1.1.0 이하는 로그인 명령이 `claude login`(존재하지 않는 명령)이라 ⓔ가 통과할 수 없고, v1.0.0은 대시보드 폴더가 `tools\dash`라 "재부팅 → 프록시 자동 기동"도 통과할 수 없다. 이 판부터 영혼 폴더는 `C:\IRIS` 고정이다(개발 PC 연습은 `IRIS_INSTALLER_SOUL_NAME`). 이 zip **이전에 만들어진 zip으로는 시험하지 않는다** — 그 zip들에는 `lib/`·`lock.json`이 빠져 있어 어느 PC에서도 설치기가 뜨지 않는다(2026-09-12 최종 검토 C1·C2).

`docs/설계.md` 6-4절의 "3층 실행 검사"가 이 문서다. 정적(`verify/static.mjs`)·재현성(`verify/reproduce.mjs`)은 자동으로 매 빌드 돌지만, 이 층은 **사람이 실제 새 컴퓨터에서 완주해 대장에 기록**해야 한다 — 배포 전 필수(6-4절 표 3행). 항목은 `docs/설계.md` 7절(수용 조건, 전부 ✓여야 출고)을 그대로 옮긴 것이며, 각 항목 아래 "확인 방법"은 어떤 로그·화면·파일을 보고 ✓/✗를 판정하는지 설명한다.

## 사용법

- 대상 PC(6-4절 "새 컴퓨터" 3단계 중 하나: ① 이 PC의 새 로컬 사용자 계정 ② VirtualBox + Windows 11 평가판 ③ 실제 베타 테스터 PC)에서 위에서 아래로 순서대로 진행한다.
- 각 항목을 통과하면 `□`를 `■`로 바꾸고, 시각·PC 식별(닉네임으로, 실제 소유자명 금지)·비고를 옆에 적는다.
- 하나라도 실패하면 즉시 멈추고 원인을 `docs/검증기록.md`에 회차를 나눠 기록한 뒤, 원본을 고치고 재빌드 → 검사소 1층·2층부터 다시 통과시킨 다음 이 체크리스트를 처음부터 다시 돈다(부분 재시험으로 통과 처리하지 않는다).

## 체크리스트

```text
□ zip 풀고 IRIS-설치.cmd 두 번 클릭 → 브라우저 설치 화면이 뜬다
```
확인 방법: 압축을 푼 폴더에서 `IRIS-설치.cmd`를 더블클릭한 뒤, 몇 초 안에 기본 브라우저가 자동으로 열리고 설치 화면(installer의 `ui/index.html`이 렌더한 페이지)이 보이는지 눈으로 확인한다. 안 뜨면 `installer/server.mjs`가 콘솔 창에 남긴 오류 메시지와, 그 창이 열려 있는지(=서버가 죽지 않았는지)를 먼저 본다.

```text
□ 사전검사 3개 ✓ · 이름 · 구독 선택 · 복사(전 부품 검증 ✓) · 로그인 완료
```
확인 방법: 설치 화면에서 사전검사 3개(디스크 여유 공간·OS 버전·기존 설치 충돌 등, 화면에 표시되는 항목)가 모두 ✓로 바뀌는지, 영혼 이름 입력 단계와 구독(Claude/Codex) 선택 단계가 정상 진행되는지, 복사 단계에서 부품별 진행률이 끝까지 차고 "전 부품 검증 ✓"가 뜨는지, 마지막으로 로그인 창(claude/codex CLI의 로그인 흐름)이 완료되는지를 화면에서 순서대로 확인한다. 복사 단계의 검증 결과는 `package-install.log`(설치 대상 폴더 루트)에도 부품별로 남는다.

```text
□ Face 창이 뜨고 첫 세션에 첫 요청문이 자동으로 들어간다
```
확인 방법: 로그인 완료 직후 IRIS-Face 창이 자동으로 열리는지 확인한다. 새로 열린 첫 세션의 입력창(또는 대화 로그)에 세팅가이드가 정한 "첫 요청문"이 사람이 타이핑하지 않았는데도 이미 들어가 있는지 확인한다 — 이 문구는 설치 대상 폴더의 `first-request.txt`(또는 그 내용을 복사해 만든 것)와 일치해야 한다.

```text
□ 에이전트가 영수증을 읽고 재설치 0건 (로그로 확인)
```
확인 방법: 에이전트가 세팅을 진행하는 동안 `package-receipt.json`을 읽는지, 그리고 이미 설치된 부품(예: 동봉 런타임·에이전트 CLI)을 다시 내려받거나 다시 설치하려는 시도가 0건인지 콘솔 로그·에이전트 대화 로그에서 확인한다. `package-receipt.json`의 `steps`(또는 동등한 필드)에 각 부품의 설치 완료 기록이 남아 있어야 하며, 이 세션 동안 그 기록이 다시 갱신(재설치로 인한 재기록)되지 않아야 한다.

```text
□ 에이전트가 세팅을 끝까지 마치고 가이드 10절 완료 보고를 낸다
```
확인 방법: 에이전트(Claude 또는 Codex)가 세팅가이드(`_setup-guides`의 v10 가이드, 해당 에이전트 판)를 처음부터 끝까지 따라가는지 대화 로그로 지켜보고, 마지막에 가이드 10절이 요구하는 형식의 "완료 보고" 메시지를 실제로 출력하는지 확인한다. 중간에 멈추거나 사람에게 되묻는 지점이 있으면 실패로 기록한다.

```text
□ 재부팅 → 바탕화면 아이콘으로 Face가 다시 뜬다 · 프록시가 자동 기동된다
```
확인 방법: 위 과정을 마친 PC를 재부팅한 뒤, 바탕화면에 생성된 IRIS-Face 아이콘을 더블클릭해 Face 창이 다시 정상적으로 뜨는지 확인한다. 동시에 TeamClaude 프록시(포트 3456)가 사람이 따로 켜지 않아도 자동으로 기동돼 있는지 — Face의 `/api/health`(또는 동등한 상태 표시) 화면에서 프록시 연결 상태가 정상으로 보이는지로 확인한다.

```text
□ 설치기 재실행 → "기존 영혼" 분기 → 아무것도 덮어쓰지 않는다
```
확인 방법: 같은 PC에서 같은(또는 새) `IRIS-설치.cmd`를 다시 실행했을 때, 처음 설치 흐름이 아니라 "기존 영혼 발견" 분기로 들어가는지 화면 문구로 확인한다. 재실행 전후로 기존 R/D/P 자료·설정·시크릿 파일의 수정 시각과 내용이 변하지 않았는지(원한다면 주요 파일 해시를 재실행 전후로 비교) 확인해, 실제로 아무것도 덮어쓰지 않았음을 검증한다.

```text
□ 한글 영혼 이름(C:\비서)으로 위 전부 재시험 (실패하면 영문 제한 확정)
```
확인 방법: 새 대상 PC(또는 초기화한 같은 PC)에서 이번에는 영혼 이름을 한글(예: `C:\비서`)로 입력해 위 8개 항목을 처음부터 전부 다시 시험한다. 경로에 한글이 섞여도 복사·로그·CLI 실행·PATH 등록이 전부 정상 동작하는지 확인한다. 어느 한 항목이라도 한글 경로 때문에 실패하면, 그 사실과 실패 지점을 `docs/검증기록.md`에 남기고 설치기의 영혼 이름 입력을 영문 전용으로 제한하는 결정을 확정한다.

```text
□ 정화 0건 · 재현성 통과 · 이 PC의 Face·대시보드·가이드 원본 무접촉(해시 전후 동일)
```
확인 방법: 이 실행 시험을 진행한 개발/빌드 PC에서 `node verify/static.mjs`(정화·검사 ①~⑨ 전부 OK — ⑨는 풀린 zip의 설치기 서버를 실제로 띄워 `/api/health`를 확인한다)와 `node verify/reproduce.mjs`(재현성 통과)를 다시 실행해 결과를 확인한다. 아울러 이번 실행 시험이 참조만 하고 절대 고치지 않아야 하는 원본 3종 — IRIS-Face(P02) 저장소, TeamClaude 대시보드, `_setup-guides`의 가이드 원본 — 의 관련 파일 해시(sha256)를 시험 시작 전·후로 비교해 동일함을 확인한다.
